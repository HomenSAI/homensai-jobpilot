HomenS.AI JobPilot

The author has approved this name. The planned GitHub repository name is homensai-jobpilot; publication is a separate stage.

This is currently documentation, not a working system. Commands, mail integration, the questionnaire, generators and dashboard have not yet been implemented. What the package actually contains.

A local Codex or Claude Code agent and a project folder support job discovery, tailored applications, reply tracking and reports. Small local tools will enforce quotas and operation states.

First, build a master profile from documents and the person's answers, with facts confirmed by the user. Then tailor a CV to a specific vacancy. A short existing CV is not treated as a complete biography.
The static statistics page is required. The agent updates an HTML snapshot; the user opens it locally to view tables. The page runs without a server, Docker or network requests. It does not edit the database or access Gmail.
An original concept by Serhii Khomenko · independently implemented. The requirements grew from his own workflow. Code from the reviewed GitHub projects has not been used and will not be used; the links below provide market context only.

Getting started: a folder, a local agent and statistics

The extracted project folder and a local agent, Codex or Claude Code, are required. English is the primary documentation language; a complete Russian edition lives in the same project. CV, cover letter, email and report languages are selected independently.

Start with Codex

  1. Install ChatGPT Desktop from the official download page, sign in and select Codex.
  2. Download the published project ZIP and extract it into a dedicated local folder.
  3. In Codex, use Projects → Add local project/Open folder, select the extracted project root and make it the primary folder.
  4. Create a new chat within this local project.
  5. Select Ask for approval and grant access to the project folder.
  6. Ask the agent to read the README, user guide, rules and specification. The future working release will also include AGENTS.md and TODO_FOR_AI.md.

This package currently contains design documents. The README provides a starting prompt for this stage; it does not run tools that have not been implemented.

What the agent does

It checks the folder and available tools, asks for missing information, performs authorized actions and records the results. A path pasted into a message is not enough: the folder must be opened as a local project with file access.

In the future release, a new chat starts with run.resume, which reads saved state, unfinished operations and the next action. Chat history does not replace the project journal.

The agent updates separate profile snapshots at dashboard/profiles/<profile_id>/summary.json and index.html. The local entry page, dashboard/index.html, opens the selected profile. Each page shows tables by year and month, with date sorting and filters.

Architecture 1.2: commands do the work, files preserve the state

The agent researches the market and drafts text. Small local tools enforce the rules and record results. Each tool runs a command and exits; no persistent server or Docker is required. The diagram describes the future implementation.

Each person has one authoritative journal, persons/<person_id>/journal/transactions.jsonl, and one writer.lock. Profile registries, the queue, inf.txt and statistics can be rebuilt from that journal. Multiple search profiles share one quota, and a new chat can resume work without sending an application again.

Commands such as run.resume, send.preflight, send.execute and snapshot building are specified but not yet implemented. The mail adapter reports its actual capabilities; connecting an account alone does not establish that automated sending works. Detailed architecture · Data contract.

The journey of one application

The agent coordinates the workflow in chat; verifiable state is saved in the project folder.

  1. ProfileA CV, source documents and a questionnaire with confirmed facts.
  2. DiscoveryCompanies and jobs within the chosen radius, prioritizing nearby locations and practical journeys.
  3. MatchingJob requirements are compared with the person's confirmed experience.
  4. DocumentsA tailored CV, cover letter, email text and visual PDF check.
  5. SchedulingImmediate, every working day or alternate days, respecting time, holidays and the quota.
  6. GmailAn authorized connection, recipient and attachment checks, and full-thread review.
  7. MonitoringReplies, delivery failures, sent evidence and deduplicated events.
  8. ReportA summary in the chosen language, plus a separate page of market recommendations.

The user selects a radius and travel by car or public transport. Journey time, transfers, walking distance and the evening return are assessed. Adding towns does not change the user's priorities; the search area expands gradually.

A master profile: more than a résumé

The user saves an existing CV and supporting material in the local profile folder, or completes a questionnaire. The agent presents extracted facts and their sources for confirmation. The full biography stays in the project; each application includes only the relevant parts.

Experience

Employers, roles, dates, responsibilities, tools, teams and results.

Education

School, vocational training, university, courses, qualification recognition, diplomas and certificates.

Skills

Languages, digital and technical skills, proficiency and supporting examples.

Projects

Internships, volunteering, a portfolio, informal learning and achievements.

Preferences

Target roles, work arrangements, radius, transport, travel time and schedule.

Languages and reports

Independent language choices for the CV, cover letter, email and report; an optional report template.

Sources

A document or self-description, date, verification status and permission to use it.

A neutral report in the selected language. The agent works on a copy of the user's template and preserves the original. Without a template, it creates a table showing surname, first name, period, submission date, company, vacancy, channel, reply date and a concise outcome. Institutional fields and third-party branding are not added automatically. Missing replies are labeled in the report language; an actual reply is summarized by its reason or decision, not by whether a thank-you was sent.

A questionnaire that supports tailored documents

The master profile holds a broad record of confirmed skills and experience. For each application, the agent produces a concise, readable CV in the selected language.

What the profile records

Education and training, experience in each role, languages, digital and professional skills, projects, achievements, volunteering, certificates and source documents. It also captures measurable results, tools, STAR examples, target roles and mobility.

What the employer receives

Only selected, verified facts relevant to the vacancy. The full biography stays local; sensitive information and a photograph are not collected by default.

One database, organized by month

Files with stable identifiers

UTF-8 JSON/JSONL, without SQL. Organizations, branches, vacancies, applications and replies are separate entities. Each person has one authoritative journal; profile records, the queue and statistics are rebuildable views.

Data, states and recovery.

Operating rules

  • Main actions take place in a local Codex or Claude Code chat. The TODO describes task order; evidence of completed actions belongs in the journal.
  • Initial setup uses draft mode. The queue is stored in the folder and processed by the agent.
  • No more than 44 actual CV submissions per person per calendar month, across every profile and channel. Resubmissions and replacements after delivery failures use a slot; a subsequent bounce does not return it.
  • The plan distributes submissions across permitted working days and blocks the 45th send. Applications made outside the system must also be recorded; an unverified quota balance is not treated as available.
  • Reports show consumed, reserved and remaining slots. A prepared folder or scheduled date is not evidence of sending.
  • Invitations, positive replies and questions require the person's decision.
  • Confirmed delivery failures are preserved. At most one suitable new company is prepared as a draft by default; automatic replacement requires separate authorization for that profile.
  • A question about the earliest available internship dates is allowed only under the profile's approved rules, after reading the thread and checking that it has not already been asked.
  • The monthly report is neutral, in the selected language, uses the user's template when supplied, and includes a separate page of market recommendations.
  • Gmail messages are not deleted or archived, and labels are not changed.
  • The static HTML page displays data and sorts rows. Personal documents and credentials are never published on GitHub.

Privacy and confirmed facts

Separate profiles

Each person has separate documents, an account and a journal. Their search profiles share the 44-submission quota; different people's data is kept separate.

Traceable facts

Facts are linked to documents or confirmed self-descriptions. The AI must not invent dates, achievements, skills, certificates or language proficiency.

Authorized access

OAuth applies to the chosen account and required actions. Secrets are held by the connection mechanism, outside the publishable project; actions are checked against profile permissions.

An experimental product and its terms of use

JobPilot helps organize the workflow. Results produced by external AI agents need to be checked for accuracy and completeness.

Research and interpretation

Company and vacancy searches, requirement extraction, summaries and proposed reply classifications are performed by the selected external agent, such as ChatGPT/Codex or Anthropic/Claude, using the sources it finds. JobPilot defines the workflow, keeps records and helps prepare documents and track progress. It does not guarantee complete market coverage or correct interpretation of every fact.

Reviewing results

Vacancy availability, current contact details, route accuracy and employer replies are not guaranteed. Before deciding or sending, users check the employer, requirements, dates, documents and recipient. The product is used at the user's own risk; users remain responsible for their decisions and the information they share.

Connections and permissions the user configures

A specification file cannot grant folder or mail access. The user selects a local project, connects the correct account and enables screen control when it is actually needed.

The folder and Codex

  • Sign in to ChatGPT Desktop, select Codex and open the extracted root as a local project.
  • Allow reading and writing within this folder; actions outside it require separate permission.
  • Naming a project “Job search” does not grant file access without an attached local folder.
  • Check the actual permissions in the interface and available status information. This project does not require full disk access or administrator mode.

Gmail and OAuth

  • Connect a supported Gmail tool and verify the exact account address.
  • Folder and mail access are configured separately.
  • Keep read and send permissions distinct; do not put passwords or tokens in chat or project files.
  • Check the tool's actual capabilities. If a required action is unavailable, continue preparing locally and report the limitation.

Mouse and screen

When needed, install and enable Computer Use, then allow the required applications in Settings → Computer Use. On Windows, the target window must be visible on the active desktop.

Running again

An available Scheduled task can wake the agent. The local computer and application must be running, and the folder must be accessible. Otherwise, the user starts a new chat manually and resumes from saved state.

Available capabilities

Reading, sending, SENT verification, search, routes and rendering are checked separately. Invitations, questions and decisions requiring unknown information are referred to the user.

What version 1.2 clarifies

One journal per person

Quota changes and actions are recorded in one transaction under a shared writer.lock. Multiple profiles do not maintain competing authoritative journals.

Resuming after interruption

A new chat uses run.resume. An uncertain send requires reconciliation; running again does not mean sending again. Views can be rebuilt from the journal.

Two documentation editions

English is primary; Russian is included in the same project. Documents and statistics use one data revision, while application and report languages are chosen separately.

Version 1.1 rules remain: three replies to one application are three events but only one application with a reply; a late reply belongs to its receipt month. Reports preserve revisions. Acceptance scenarios define checks for quotas, calendars, recovery, Gmail, documents and HTML; having scenarios does not mean working software has passed them.
