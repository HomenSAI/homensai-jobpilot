Він читає версію з найновішого розділу `CHANGELOG.md`, записує `VERSION` назад у `main` і створює реліз на GitHub. Він не перевіряє публічний список файлів, персональні дані чи секрети. Супровідник завершує цей контрольний список **до** того, як зміна потрапить у `main`, бо робочий процес публікує автоматично.

Виконуйте ці перевірки на синтетичних тестових даних і на архіві-кандидаті випуску. Не запускайте реальний випуск, щоб перевірити контрольні перевірки.

## 1. Публічний список дозволених файлів (відмова при помилці)

Публічний випуск може містити лише файли нижче. Будь-який інший файл зупиняє випуск, доки його не буде видалено або доки список не буде змінено в перевіреному коміті.

- Кореневі документи: `README.md`, `USER_GUIDE.md`, `OPERATING_REQUIREMENTS.md`, `AGENTS.md`, `CLAUDE.md`, `TODO_FOR_AI.md`, `AI_BUILD_SPEC.md`, `ARCHITECTURE.md`, `DATA_CONTRACT.md`, `ACCEPTANCE_TESTS.md`, `REVIEW.md`, `RELEASE_CHECKLIST.md`, `CHANGELOG.md`, `VERSION`, `LICENSE`, `LICENSE-DOCS`, `NOTICE`, `PROJECT_OVERVIEW.html`, `overview_*.html`, `.gitignore`.
- Папки: `docs/` (російська редакція та її файли), `dashboard_template/` (чисті шаблони і зразковий `summary.js`), `examples/` (лише нейтральні приклади), `assets/` (спільні стилі, скрипти і шрифти IBM Plex), `.github/workflows/`.
- Під `Локальные_данные/`: лише порожні папки для прийому і їхні файли `README.md`, а також `Вопросы_для_рассказа.md`, як дозволяє `.gitignore`. Жодного іншого файлу і жодної підпапки з даними.

## 3. Перевірки вмісту

Виконуйте перевірки вручну. Автоматичний сканер може допомогти, але це лише одна з перевірок.

- **Персональні дані.** Жодних справжніх імен, крім публічного підпису автора, жодної особистої адреси електронної пошти, номера телефону, домашньої адреси, дати народження, посвідчення людини чи номера рахунку. Дозволені лише публічний контакт автора та очевидні заповнювачі, як-от `first.last.job@gmail.com`, що є шаблоном, а не справжньою адресою. Не використовуйте адресу реальної людини як приклад.
- **Схожі на справжні дані.** Жодного реалістичного резюме, диплома, сертифіката, рекомендації, супровідного листа, запису про вакансію, контакту компанії чи уривка пошти. Приклади мають бути очевидно синтетичними, використовувати заповнювачі в дужках або явно вигадані імена і не видавати себе за контакт справжнього роботодавця.
- **Секрети.** Жодних токенів, паролів, одноразових кодів, значень OAuth чи сеансу, cookie, ключів API або приватних ключів. Шукайте типові шаблони (наприклад, `BEGIN PRIVATE KEY`, `ghp_`, `AKIA`, `ya29.`, `sk-`, `Bearer `, `password`, `token`, `cookie`) і перевіряйте кожне знайдене вручну.
- **Приватні матеріали.** Жодного приватного тестового набору, справжнього тексту листів, справжнього тексту вакансій, статистики реальної людини, знімка екрана з персональними даними або копії робочої папки.
- Записуйте, які пошуки виконано і що переглянуто вручну. Чистий результат пошуку не доводить, що персональних даних немає.

## Версія на main

`CHANGELOG.md` — джерело версії випуску. При кожному push у `main` або ручному запуску Release GitHub Actions читає найновіший заголовок `MAJOR.MINOR.PATCH` і за потреби автоматично записує `VERSION`. Повторний запуск зберігає наявний випуск і тег. Некоректні, дубльовані, невпорядковані або понижувальні версії зупиняють публікацію. Звичайний push у Git не може перезаписати новіший main; якщо main змінився під час синхронізації, запустіть робочий процес знову. Поточні позначки документів посилаються на `VERSION` і не містять власних номерів. SHA коміту позначає конкретний коміт; `VERSION` позначає випуск пакета, а не кожен коміт. GitHub Actions — це автоматизація випуску; вона не додає до пакета користувача відправника чи фонового застосунку.
