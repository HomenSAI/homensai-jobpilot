# HomenS.AI JobPilot — перевірка і статус

## Обсяг перевірки для цієї редакції

Що запускали, хто і чим, аж до цієї версії. Ніщо з цього не використовувало реальний обліковий запис Gmail, реального роботодавця, Codex чи власний Claude Code користувача.

- **Виконувана модель правил** (`examples/simulation/SIMULATION_REPORT.md`): тестувальник реалізував письмові правила як одноразову модель зі змодельованою поштовою скринькою. Пройшли 46 перевірок: п'ять заявок із відповідями, відмова, збій доставки і помилка пошти, подвійне надсилання, ліміти, два чати, перервана робота. Знайдено й виправлено дві невідповідності в правилах (1.17.1).
- **Пробні проходи першого налаштування**: агент Claude у пісочниці з копією пакета дотримувався `CLAUDE.md`, `AGENTS.md` і `TODO_FOR_AI.md` для трьох вигаданих людей (нічого не підготовлено; папки заповнено; довга голосова розповідь) аж до етапу `ready`. Їхні висновки враховано у версії 1.18.0. Для конвертації і відтворення шаблонів там використовувався LibreOffice.
- **Сторінка статистики**: відкрита в headless Microsoft Edge російською й німецькою (блок вартості часу, смуги ліміту); раніше — перевірки валідатора знімка (18 у JavaScript VM). Макет на телефонах, роботу з клавіатури й друк не перевіряли.
- **Шлюз приватності**: `.github/workflows/privacy-gate.yml` запускали локально на чистій копії (пройшов) і на копії з підкладеними персональними даними (не пройшов, як і очікувалося); на GitHub він ще не запускався.
- **Не запускали**: Codex; Claude Code користувача; реальний Gmail (читання, доказ SENT і Scheduled, вкладення); Word; реальних користувачів; заплановані завдання.

## Де зараз проєкт

**У цьому випуску:** двомовні процедури роботи; оновлені README, авторська історія та окремі повідомлення про ліцензії коду й документації; розширені контракти журналу і графіка; виправлення перевірки знімка статистики, історичних лічильників, порожнього вибору місяця, відображення спільного ліміту та порядку результатів.

**Перевірено в цій роботі:** 18 цільових VM-перевірок сторінки статистики пройшли, зокрема зіпсовані знімки, дубльовані ідентифікатори відповідей, пізні відповіді, вибір порожнього місяця, відсутні підсумки спільного ліміту і сортування технічних помилок. Це не повний тест у браузері й не цикл приймальної перевірки агента або Gmail. Ці перевірки належать до ранішої робочої копії (1.5.1).

**Середовище розробки:** проєкт розроблено, локально перевірено та віртуально перевірено в середовищі **Codex**. **Anthropic / Claude Code не тестувалися в цьому циклі**; їх сумісність не підтверджена. Перевірки Codex не є повною сертифікацією проєкту, а незалежна повна приймальна перевірка вихідного агента лишається неповною.

**Ще не зроблено:** повна ручна приймальна перевірка робочого процесу агента; реальне підключення Codex або Claude Code; реальне заплановане надсилання Gmail і обробка відповідей; відтворення DOCX через Word; перший запуск робочих процесів випуску і шлюзу приватності на GitHub. Gmail, роботодавці та зовнішні API ШІ не підключалися.

Робочий процес навмисно не має окремого застосунку для пошуку роботи чи надсилання листів. Сторінка статистики містить HTML/CSS/JavaScript для перевірки, сортування, фільтрації та показу знімка, підготовленого агентом. Запобіжники для згоди, ліміту і зовнішньої пошти лишаються процедурами, а не технічними замками. Версії 1.2–1.4 встановили двомовну архітектуру, журнал в межах однієї людини та плейбук агента; версія 1.5 розширює місячний робочий процес, звірку з Gmail, локальні архіви, звітність, файли атрибуції та перевірку знімка статистики.

Огляд охоплював AI_BUILD_SPEC.md, HTML-огляд і посібник користувача. Особисті архіви, Gmail і наявні заявки не змінювалися. Код із переглянутих альтернатив на GitHub не використовувався. Огляд перевіряє узгодженість проєкту; це не аудит зовнішніх сервісів або ринку праці.

## Виявлені прогалини та виправлення

| Прогалина | Виправлення |
|---|---|
| Немає вхідного README; для старту потрібні були файли, яких не існувало | README перелічує файли, які справді існують, і відокремлює збірку документації від майбутнього випуску |
| Формат бази даних лишався відкритим | JSON/JSONL без SQL; DATA_CONTRACT визначає ідентифікатори, шляхи, авторитетні записи і проєкції |
| Специфікація спільно використовувала звіти і журнали, тоді як HTML тримав їх у профілях | Звіти і журнали належать профілю; ліміт належить людині |
| «Атомарний ліміт» не має незалежного механізму виконання | Проєкт описує маркер єдиного автора запису, резервування, ідентифікатори дій і відновлення; це лишаються процедурні захисти, а не технічні замки |
| Невизначене надсилання могло спричинити дубль | `send_uncertain` зберігає резервування і вимагає звірки з доказом замість сліпого повтору |
| Відповідь, доставка і подяка могли злитися в один статус | Подання, доставка, результат і подальші дії мають окремі стани |
| «Відповіді» могли означати або повідомлення, або заявки | Окремі лічильники для подій відповіді та для заявок з відповіддю, зокрема пізніх |
| Звіт, складений в останній робочий день, міг пропустити пізніші відповіді | Маніфести, ревізії і розподіл за місяцем фактичного отримання |
| Ринковий аналіз став необов'язковим | Окрема ринкова сторінка знову обов'язкова; недоступні джерела дають «estimate unavailable» |
| «Локальне» зберігання могли сплутати з «без передачі в хмару» | Згода передує читанню оригіналів хмарним агентом; експорт анкети — явна дія |
| Статичний файл міг нібито виявити пізнішу невдалу перевірку | Ідентифікатори знімка, час оновлення і те, що насправді може показати застаріла сторінка, описані прямо |
| Публічні документи містили приватні приклади попередніх дозволів | Замінено загальною політикою імпорту, яка ніколи не активує дозволи автоматично |
| HTML показував різні версії; заповнювачі назв файлів розбиралися як теги | Версії синхронізовано, заповнювачі екрановано, додано навігацію |
| Огляд був однією дуже довгою сторінкою | Розділено на короткі сторінки з меню; додано сторінку статистики |
| Порядок встановлення (спершу агент чи архів) був незрозумілим | Посібник пояснює порядок: агент, потім архів, потім підключення; кожен крок каже, що має з'явитися на екрані |
| Готовність виражалася лише широкими намірами | Конкретні сценарії приймання з вхідними даними та очікуваними результатами |

## Фіксовані рішення

Назва продукту — **HomenS.AI JobPilot**, репозиторій — `homensai-jobpilot` ([HomenSAI/homensai-jobpilot](https://github.com/HomenSAI/homensai-jobpilot)). Авторство і візуальна ідентичність (як на homensai.com і в HomenS.AI Core) збережені. Агент і папка обов'язкові; Docker не використовується; HTML-сторінка лише показує дані; ліміт — 44 подання на людину за місяць. Ближчі цілі розглядаються першими, резюме і листи персоналізуються, мови незалежні, звіти нейтральні, поштові дії потребують власної згоди, а код із переглянутих альтернатив не використовується повторно.

## Статус можливостей (R09)

Жодна можливість не позначається як перевірена на практиці, якщо немає зафіксованого запуску.

## Роботи, які ще не перевірено або не реалізовано

- Інструкції робочого процесу повністю не прийняті з реальним користувачем Codex або Claude Code. Пакет лишається експериментальним; сценарії ще належить виконати в чаті на синтетичних даних.
- Можливості Gmail-коннектора та вбудованого браузера потрібно перевірити окремо на встановленому обліковому записі користувача, зокрема читання цілих ланцюжків листування, Gmail Scheduled, вкладення, доказ SENT і відновлення після перерваного сеансу. Для цього огляду жодного реального облікового запису Gmail не підключали.
- Створення DOCX/PDF і відтворення сторінка за сторінкою в Word або LibreOffice агентом від початку до кінця не виконувалися.
- Повний покроковий порядок налаштування для Claude Code не написано; детальний посібник зі встановлення — для Codex у Windows.
- Робочий процес випуску і шлюз приватності (`.github/workflows/privacy-gate.yml`) ще потребують першого запуску на GitHub. Ручний контрольний список випуску залишається.
- Спільний місячний ліміт 44 на людину, погодження, дії Gmail, планування, архіви та доставка звітів є процедурами, а не жорсткими замками чи гарантованими фоновими службами.
- Щоденний звіт через Gmail (R08), твердження про ціни та тарифи (перевірено на офіційній сторінці цін 8 жовтня 2026 року; відтоді повторно не перевірялося) і двосторонній перегляд документів (R19) потребують зафіксованого запуску, перш ніж їх можна буде назвати перевіреними.
- Нейтральні шаблони резюме, супровідного листа і звіту є лише англійською та українською; німецьких і російських немає.

`.gitignore`, приклад налаштувань і шаблон статистики можна переглянути локально, але вони не доводять, що робочий процес агента працює. Твердження PASS для сценаріїв агента не ставляться без зафіксованої ручної перевірки і доказів.

## Зміни в документаційному проході 1.6.0

- Експлуатаційні вимоги: формулювання про платний тариф і застереження щодо умов (R10); два способи додати документ і крок підтвердження (R19); щоденний звіт через Gmail з його правилами згоди й дублікатів (R08); обмеження завантаження через вбудований браузер; блок перегляду перед надсиланням (R18).
- Посібник користувача: меню «Не знаєте, з чого почати?» з простими кроками (R15); крок про платний тариф і умови (R10); приклад тексту листа для вікна Gmail з приміткою, що це приклад (R14); блок довідки і блок перегляду (R18); два способи додати документ (R19); позначки можливостей (R09).
- Розділ про ідею (R11) у README в обох редакціях.
- Контрольний список випуску: список дозволених файлів, перевірка архіву та індексу, перевірки вмісту і запис перевірки (F10).
- Нічого в цьому проході не запускалося: ні перевірки агента, Gmail, браузера, планувальника чи відтворення, ні повторна перевірка статистики.

Це не повна приймальна перевірка браузера, агента ШІ, Gmail, запланованого надсилання чи відтворення документів. Жодного зовнішнього облікового запису або API не підключалося.
