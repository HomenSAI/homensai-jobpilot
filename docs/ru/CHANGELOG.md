# История изменений

[English](../../CHANGELOG.md) | [Русский](CHANGELOG.md)

Версия проекта записана в файле [VERSION](../../VERSION). Проект — это комплект документации, по которому работает ИИ-агент; отдельной программы нет, поэтому это версия комплекта (документы, примеры и страница статистики).

Правила: `MAJOR.MINOR.PATCH`. MAJOR меняется, когда формат данных или правила изменились так, что старые данные не подходят. MINOR — новая функция или новая часть документации. PATCH — исправление или правка формулировок без новых возможностей. Каждое изменение в `main` добавляет строку сюда; номер повышается при выпуске. Каждый выпуск получает git-тег `vX.Y.Z`.

## 1.4.2 — 08.10.2026

Проверка логики всего комплекта; противоречия убраны.

- Прерванная первая настройка продолжается: `AGENTS.md` и `TODO_FOR_AI.md` говорят, что делать, если `workspace.json` есть, а `stage` не `ready`, с таблицей «сохранённый этап → следующий шаг» (раньше агент перешёл бы сразу к ежедневной работе).

- Ритм отправки: только варианты, которые есть в настройках (каждый допустимый рабочий день, каждый второй допустимый рабочий день); вопрос про «календарный день» убран.
- Проверка перед отправкой: формулировка лимита точная (это письмо даёт не более 44). Правило подсчёта: месяц — местный месяц человека; строки около границы месяца по UTC проверяются вручную.
- Сценарии приёмки FIRST-09 и FIRST-10. Дата выпуска в README исправлена.

## 1.4.0 — 07.10.2026

Агент теперь может начать сам, а человеку понятно, что и куда класть.

- **Файлы инструкций для агента существуют** как черновики: `AGENTS.md` (правила, их загружает Codex), `CLAUDE.md` (его загружает Claude Code, подключает `AGENTS.md`) и `TODO_FOR_AI.md` (первый запуск, продолжение, списки проверок для стандартных действий). Человеку достаточно сказать «Начинай»; агент представляется и задаёт по одному вопросу.
- **Готовые папки для материалов человека:** `Локальные_данные/Положите_сюда/` с `1_Мои_документы`, `2_Рассказ_о_себе` и `3_Шаблон_отчёта` (в каждой короткая инструкция, а также список вопросов для рассказа). Они входят в ZIP; личные файлы внутри Git игнорирует (`.gitignore` обновлён).
- **База знаний:** один Markdown-файл на человека, `persons/<person_id>/База_знаний/Жизнеописание.md` — всё жизнеописание в виде фактов с источником, статусом (`proposed` / `confirmed` / `rejected`), `use` и `sens`. Формат — в DATA_CONTRACT.md §3a. Факты подтверждает человек; в резюме идут только подтверждённые.
- **Интервью вместо формы:** агент проводит интервью по темам, голосом или текстом, и после каждой темы дословно сохраняет ответы. Описано и то, как заранее рассказать о себе голосом в любом чате Claude или ChatGPT.
- **Первый запуск** отслеживается в `workspace.json` (`stage`), поэтому прерванный первый запуск продолжается с того места, где остановился. `person_id` и `profile_id` — короткие читаемые id.
- HTML-страницы, USER_GUIDE.md, AI_BUILD_SPEC.md, ARCHITECTURE.md, DATA_CONTRACT.md и README согласованы: одна и та же картина в файле для ИИ и в HTML. Новые сценарии приёмки FIRST-01…05 и KB-01…04.
- Анкета в виде HTML-формы убрана из замысла; `source_documents/` и `templates/` у профиля заменены готовыми папками.

## 1.3.1 — 07.10.2026

- Страница статистики: данные теперь лежат в отдельном файле `summary.js` рядом со страницей. Для реального профиля агент копирует `index.html` без изменений и пишет только `summary.js`, поэтому файл страницы никогда не правят, а ошибка в данных не может его сломать. Если `summary.js` нет или он некорректен, страница сообщает об этом. `summary.json` и блок данных внутри HTML убраны.
- Решение: скриптов-помощников нет. Скрипту нужна среда выполнения, которой нет на чистой Windows, подтверждение при каждом запуске, и он не может принудить то, что агент способен пропустить; подсчёт делается штатными командами системы (см. ARCHITECTURE.md), остальное — обычные файлы.
- Автоматический выпуск: `.github/workflows/release.yml` создаёт тег и релиз на GitHub при изменении `VERSION`. Работает только на серверах GitHub и не входит в продукт.

## 1.3.0 — 07.10.2026

Проект теперь определён как только правила и файлы: **программного кода нет**. ИИ-агент следует записанным правилам и ведёт обычные файлы.

- ARCHITECTURE.md переписан: нет локальных команд, скриптов и модулей; стандартные действия — списки проверок, которые выполняет агент; в журнале одна строка на выполненное действие; правило единственного писателя — файл-метка.
- Защиты (лимит 44, «никогда не отправлять дважды», один пишущий в каждый момент) описаны прямо как порядок действий, а не технические замки. Полностью автоматическая отправка по умолчанию выключена и требует явного принятия пользователем этого ограничения.
- DATA_CONTRACT.md: убраны цепочка хешей, `command_id`, `request_hash`, `expected_revision`, `fsync` и checkpoint; оставлены `action_id` и `sequence`. ACCEPTANCE_TESTS.md: сценарии выполняются вручную в чате на синтетических данных и записываются в журнал.
- AI_BUILD_SPEC.md: этапы работы переписаны (файлы инструкций в Markdown вместо реализации); утверждения о коде убраны. Файл `examples/command.example.json` удалён.
- Страницы обзора и README приведены в соответствие.
