Установка

Установка шаг за шагом

Установка занимает около 30–40 минут. Выполняйте шаги по порядку. В каждом шаге написано, что должно появиться на экране, — так сразу видно, получилось ли. Git, Python и другие средства разработки на вашем компьютере не нужны.

Порядок

Что сначала: агент или архив?

Сначала агент, потом архив, потом вы соединяете одно с другим. Агент первым потому, что его доступность зависит от вашего аккаунта: лучше узнать это сразу, а не после того, как всё остальное подготовлено. Архив — просто папка с файлами; пользу он приносит, когда агент её открывает.

Часть 1 · АгентУстановить ChatGPT Desktop, войти в аккаунт и убедиться, что доступен Codex. Шаг 1
Часть 2 · Папка проектаСкачать архив проекта с GitHub через браузер и распаковать его в папку. Шаг 2
Часть 3 · Соединить и запуститьОткрыть папку как локальный проект, задать разрешения и сделать первый безопасный запуск. Шаги 3–6

Дальше вы добавляете свои данные (шаги 7–9), при желании подключаете почту (шаг 8) и переходите к ежедневной работе (шаги 10–13).

Статус пакета. Это руководство описывает готовый выпуск. Сейчас в папке — проектная документация, а не готовый к запуску продукт и не опубликованный архив выпуска. Не скачивайте архив по ссылке, которую нельзя проверить. Репозиторий: github.com/HomenSAI/homensai-jobpilot. Для текущей версии документации начните с README: там перечислены реально существующие файлы и дан стартовый запрос, которому не нужен ещё не созданный файл задач.

Перед началом

Что понадобится

Компьютер и аккаунты

  • Компьютер с Windows и доступом в интернет.
  • Аккаунт ChatGPT, в котором доступен Codex (проверяется на шаге 1).
  • Аккаунт Gmail — только если нужен учёт почты.

Ваши материалы

  • Исходное резюме и, если есть, подтверждения опыта, образования и навыков.
  • Языки для документов заявок и для отчётов.
  • Отдельная папка для проекта, например Documents\HomenSAI-JobPilot.

Для работы с файлами нужен локальный проект Codex, открытый на вашем компьютере. Обычный облачный проект ChatGPT не даёт доступа к папке на компьютере.

Часть 1

Агент

  1. Установите ChatGPT Desktop и войдите в аккаунт

    1. Откройте официальную страницу загрузки ChatGPT.
    2. Скачайте и установите версию для Windows, запустите её и войдите в аккаунт.
    3. В переключателе режимов выберите Codex. Не выбирайте облачный проект ChatGPT или Work: для этой работы нужна открытая локальная папка.

    Что должно появиться: главное окно с именем вашего аккаунта и переключатель режимов, в котором есть Codex.

    Если Codex нет: проверьте, доступен ли он для вашего аккаунта и организации. Не ставьте неофициальные сборки. См. Quickstart от OpenAI.

Часть 2

Папка проекта

  1. Скачайте и распакуйте архив проекта

    1. Откройте в браузере репозиторий проекта на GitHub (github.com/HomenSAI/homensai-jobpilot).
    2. Выберите Code → Download ZIP.
    3. В Проводнике создайте папку, например Documents\HomenSAI-JobPilot.
    4. Распакуйте ZIP в эту папку.
    5. Не распаковывайте в системную папку Windows.

    Что должно появиться: прямо в папке (не внутри ещё одной вложенной папки): README.md, USER_GUIDE.md, AI_BUILD_SPEC.md, AGENTS.md, CLAUDE.md, TODO_FOR_AI.md и dashboard_template.

    Если файлы на уровень глубже: архив распакован в лишнюю вложенную папку. Поднимите содержимое выше или на шаге 3 выберите внутреннюю папку.

    В этой папке будут и инструкции проекта, и ваши локальные рабочие данные. Личные профили, резюме, письма, OAuth-токены и статистику нельзя публиковать на GitHub.

Часть 3

Соедините агента с папкой и запустите

  1. Создайте локальный проект и выберите папку

    1. В Codex откройте Projects.
    2. Выберите Add local project или Open folder (точное название зависит от версии).
    3. Укажите полный путь к распакованной папке, например C:\Users\ВашеИмя\Documents\HomenSAI-JobPilot.
    4. Если проект уже создан: его меню → Edit project → Add folder, выберите папку и нажмите Make primary.
    5. Назовите проект, например Job search.

    Что должно появиться: проект в списке, а основной папкой у него — та, где лежит README.md: не отдельный файл и не родительская папка с посторонними данными.

    Важно: фразы «работай по пути …» в чате недостаточно. Папка должна быть открыта или прикреплена как локальная папка проекта. См. локальные проекты.

  2. Создайте чат для настройки

    1. Откройте новый локальный проект и выберите New chat внутри него.
    2. Проверьте, что выбраны Codex и локальная среда (Local / This computer), а не Cloud или Worktree.
    3. Назовите чат, например Initial JobPilot setup.

    Что должно появиться: чат внутри проекта, рядом с полем ввода указано «Local».

    Для настройки, поиска, ежедневных проверок и месячных отчётов можно вести отдельные чаты. Состояние между чатами хранят файлы и журнал проекта; не полагайтесь только на историю одной беседы.

  3. Задайте разрешения

    1. Откройте меню разрешений под полем ввода и выберите Ask for approval. Агент сможет работать в текущей папке и будет спрашивать перед любым другим действием.
    2. Если пункта нет, посмотрите в Settings → General → Permissions.
    3. Не выбирайте Full access, не запускайте ChatGPT Desktop от администратора и не открывайте доступ ко всему диску.
    4. Если Codex просит доступ за пределами папки, остановитесь и подумайте, действительно ли он нужен. Давайте только узкое одноразовое разрешение.
    5. Веб-поиск, файлы, почта и управление экраном — отдельные разрешения. Разрешение одного не включает остальные.

    Что должно появиться: «Ask for approval» (или аналог) в меню разрешений и папка проекта как рабочая папка.

    Официальные пояснения: режимы разрешений, sandbox.

  4. Сделайте первый безопасный запуск

    Вставьте этот текст в новый чат:

    Работай только внутри открытой локальной папки HomenS.AI JobPilot.
Сначала подтверди фактическую рабочую папку и перечисли найденные файлы.
Прочитай README.md, USER_GUIDE.md, AGENTS.md, AI_BUILD_SPEC.md и DATA_CONTRACT.md,
затем найди TODO_FOR_AI.md.
Проверь комплектность пакета и выполни только первый безопасный пункт плана.
Ничего не делай за пределами этой папки; не отправляй резюме и не меняй почту.
Если нужного файла нет, не создавай его самостоятельно: объясни, чего не хватает,
и задай только необходимые вопросы. Начни в режиме draft-only.

    Что должно появиться: агент называет правильную папку, перечисляет файлы, сообщает, что работает в режиме draft-only, и предлагает план.

    Если нет AGENTS.md или TODO_FOR_AI.md: остановитесь. Пакет ещё не является полным рабочим выпуском. Не просите агента придумать недостающие файлы.

Часть 4

Ваши данные, почта и первая очередь

  1. Создайте профиль и добавьте сведения о себе

    1. Выберите или создайте личный профиль. Не смешивайте данные разных людей. Несколько направлений поиска одного человека используют один person_id: лимит 44 общий, а не обновляется для каждого профиля.
    2. Скопируйте резюме и выбранные подтверждающие документы в Локальные_данные\profiles\<profile_id>\source_documents\ либо заполните анкету, если она есть в выпуске. До первого чтения этих файлов облачным агентом согласитесь передать выбранные сведения его провайдеру. «Локальное» хранение не означает офлайн-обработку. Можно начать с обезличенного примера.
    3. Попросите агента извлечь факты и показать их. Подтвердите, исправьте или отклоните каждую сомнительную запись. Агент не должен придумывать опыт, даты, сертификаты, уровни языка и достижения.
    4. Язык CV, сопроводительного письма / текста письма и отчёта выбирается отдельно. Язык никогда не определяется по стране, городу или языку интерфейса.
    5. Если у вас есть шаблон отчёта, положите его в папку шаблонов профиля и укажите агенту путь. Оригинал остаётся неизменным, отчёт — отдельная нейтральная копия. Без шаблона система создаст простую таблицу с вашими фамилией, именем и результатами заявок.
    6. Задайте цель, исходную точку, радиус в километрах, транспорт (машина и/или общественный), допустимое время пути, предпочтительные города, график и исключения. Для «через день» уточните: календарные дни или каждый второй допустимый рабочий день. Значения в examples/settings.example.json — примеры, а не ваши настройки.

    Что должно появиться: список подтверждённых фактов с источником для каждого и ваши настройки, повторённые для утверждения.

    Никогда не записывайте пароли, одноразовые коды и OAuth-токены в файлы профиля. Убедитесь, что Локальные_данные/ исключена из публикации.

  2. Подключите Gmail отдельно — только если нужен учёт почты

    1. Проверьте, что в выпуске указаны точное название и адрес утверждённого Gmail-инструмента или сервера и нужные разрешения. Не угадывайте адрес и не добавляйте произвольный сервер.
    2. Если выпуск использует MCP-сервер, откройте Settings → MCP servers → Add server, введите только параметры из выпуска и сохраните. Если используется подключаемое приложение, откройте страницу Apps / Connectors.
    3. Выберите Authenticate / Connect, используйте официальный экран OAuth и перед подтверждением проверьте адрес Gmail.
    4. Начните только с чтения и поиска. Отправку включайте отдельно, если она нужна. Не разрешайте удаление, архивирование и смену меток. Режим по умолчанию остаётся draft_only.
    5. Если что-либо просит ввести пароль, код или токен в чат, файл или репозиторий — откажитесь и остановите настройку.

    Что должно появиться: именно тот адрес Gmail, который вы хотели, и только утверждённые вами разрешения.

    Если коннектор ещё не опубликован: почтовая интеграция не готова. Не подставляйте другой сервер. См. MCP и OAuth.

  3. Подготовьте и проверьте первую очередь

    1. Попросите агента найти компании и вакансии в вашем радиусе и собрать источники, контакты, требования и даты проверки.
    2. Просмотрите записи, дубли, адреса и актуальность вакансий. Проверьте реальные маршруты для вашего транспорта.
    3. Попросите персональный комплект документов на выбранном языке и проверьте каждую дату, факт, получателя и вложение.
    4. Просмотрите очередь и подтвердите даты и интервалы. Не включайте массовую рассылку.
    5. Система допускает не более 44 фактических отправок резюме на человека за календарный месяц. Если остаток нельзя надёжно проверить, агент должен остановиться.
    6. До любой отправки используйте режим черновиков. Отправка разрешена только после настройки утверждённого профиля и проверки конкретного письма.

    Что должно появиться: черновики в месячных папках и очередь с точными датами и счётчиком оставшихся слотов.

    Если агент сообщает «исход отправки неизвестен», не просите просто отправить ещё раз: сначала сверьте с папкой «Отправленные» или подтверждением портала. Смена вложения или получателя требует новой проверки. Лимит темы по умолчанию — 50 символов с пробелами; это правило продукта, а не ограничение почтового сервиса.

Часть 5

Дополнительные возможности и ежедневная работа

  1. Включайте управление экраном, только если нужно

    Для поиска и работы с файлами управление мышью обычно не нужно. Если для конкретной задачи действительно нужен браузер или другое окно:

    1. В ChatGPT Desktop откройте Codex → Plugins → Computer Use и установите или включите его, если он есть в вашей версии.
    2. Откройте Settings → Computer Use и разрешите только нужное приложение.
    3. В Windows окно, которым управляют, должно быть видно на активном рабочем столе.
    4. Одобряйте только понятные вам действия. Computer Use не заменяет OAuth, доступ к папке и согласие на отправку.

    См. Computer Use. Для базовой работы он не нужен.

  2. Ежедневная работа и расписание

    Для ручной проверки откройте локальный проект, создайте чат Daily check и попросите агента прочитать правила и выполнить очередной безопасный пункт плана. Он обновит файлы и журнал и пересоберёт статистику.

    Если ваше приложение поддерживает расписание для локального проекта, сначала проверьте один ручной запуск, затем попросите Codex создать повторяющуюся задачу с нужным временем и часовым поясом. Прочитайте её текст и первый результат. Для локальных файлов компьютер должен быть включён, приложение запущено, а папка доступна; иначе запускайте проверку вручную. См. Scheduled tasks.

    Задача должна использовать ту же основную папку и журнал, а не копию или новый worktree без ваших данных. Пропущенные отправки записываются и переносятся; при включении компьютера они не отправляются «пачкой вдогонку».

  3. Откройте статистику и соберите отчёт

    1. После проверки откройте двойным щелчком созданный файл Локальные_данные\dashboard\profiles\<profile_id>\index.html. Файл Локальные_данные\dashboard\index.html — меню профилей. Сервер не нужен.
    2. Страница показывает годы, месяцы и дни. Сортируйте по дате или результату, фильтруйте и ищите. Она только для просмотра; данные обновляет агент. Попробовать можно уже сейчас на примерах: страница статистики.
    3. В конце периода попросите агента подготовить DOCX/PDF на выбранном языке и по шаблону.
    4. Проверьте фамилию, имя, период, строки заявок, а также дату и суть каждого ответа. Для заявок без ответа в отчёте стоит «ответ не получен» на языке отчёта.
    5. Отчёт сохраняется локально и никогда не отправляется по почте автоматически.

    Статистика различает число ответных писем и число заявок, получивших ответ. Ответ на старую заявку засчитывается в месяц получения. Отказ без причины записывается как «причина не указана». Отдельная страница PDF содержит рыночную рекомендацию с датой, радиусом, транспортом, проверенными источниками и охватом; недоступные оценки помечаются явно.

  4. Обновление пакета и резервная копия

    Перед обновлением скопируйте Локальные_данные/ в отдельную папку резервной копии. Скачайте новый ZIP в новую папку, сравните версии и инструкции и попросите агента перенести только подтверждённые настройки. Никогда не распаковывайте обновление поверх личных данных и не публикуйте Локальные_данные/.

Помощь

Если что-то не работает

Агент не видит файлы

Проверьте, что открыт локальный проект, а его основная папка — распакованный корень. Пути в сообщении недостаточно.

Агент не может сохранить результат

Проверьте режим разрешений и доступ к папке проекта. Не открывайте доступ ко всему диску.

Gmail не подключается

Остановитесь и проверьте официальный коннектор и его разрешения. Не вставляйте учётные данные в чат.

Нет файла правил или шаблона

Архив может быть неполным или это ещё проектная сборка. Не просите агента придумать файлы.

Статистика не открывается

Проверьте, что агент создал dashboard/profiles/<profile_id>/index.html; чистый шаблон содержит только примеры данных.

Названия меню и возможности могут меняться; перед каждым выпуском ссылки и экраны сверяются с актуальной документацией OpenAI. Claude Code можно использовать вместо Codex, но его полная пошаговая настройка пока не написана. Те же шаги есть в виде Markdown в руководстве пользователя.
