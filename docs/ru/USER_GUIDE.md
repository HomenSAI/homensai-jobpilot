# HomenS.AI JobPilot — пошаговое руководство пользователя

[English](../../USER_GUIDE.md) | [Русский](USER_GUIDE.md)

**Черновик 1.2 · 07.10.2026**
**Для:** Windows и ChatGPT Desktop с Codex. Это основной пошаговый путь для данного черновика.

Название проекта утверждено: **HomenS.AI JobPilot**. Имя будущего GitHub-репозитория — `homensai-jobpilot`; фактическая ссылка будет добавлена после его создания.

> **Статус пакета.** Это руководство описывает запуск будущего опубликованного пакета HomenS.AI JobPilot. Текущая папка содержит проектную документацию, но не готовый исполняемый продукт и не опубликованный ZIP. Перед релизом автор должен добавить настоящий адрес GitHub-репозитория, выпустить архив и включить все перечисленные ниже файлы. Не скачивайте случайный архив по неподтвержденной ссылке.

Для текущей документальной сборки сначала откройте [README.md](README.md): он перечисляет действительно имеющиеся файлы и дает стартовый запрос без требования отсутствующего TODO. Шаги ниже предназначены для полного рабочего релиза. Настройка Claude Code — альтернативный путь, но его полный пошаговый сценарий еще не включен в это руководство.

## Что понадобится

- компьютер с Windows и доступом к интернету;
- ChatGPT Desktop с доступным в аккаунте режимом Codex;
- ZIP-архив из официального репозитория HomenS.AI JobPilot;
- отдельная локальная папка для распаковки и дальнейшей работы;
- ваше исходное резюме и, если есть, подтверждения опыта, образования и навыков;
- выбранные языки резюме и отчета;
- подключение к Gmail через разрешенный в установленной версии Codex инструмент, если нужен учет писем.

Для работы с локальными файлами нужен именно **локальный проект Codex**, открытый на компьютере. Обычный облачный проект ChatGPT сам по себе не предоставляет доступ к папке на компьютере.

## Запуск в Codex: выполняйте по порядку

### 1. Установите ChatGPT Desktop и войдите в аккаунт

1. Откройте [официальную страницу загрузки ChatGPT](https://chatgpt.com/download/).
2. Скачайте и установите версию для Windows.
3. Запустите приложение и войдите в свой аккаунт ChatGPT.
4. В переключателе режима выберите **Codex**. Для этой системы не выбирайте облачный ChatGPT-проект или Work: им нужна открытая локальная папка.

Если Codex отсутствует в интерфейсе, проверьте доступность функции для вашего аккаунта и организации. Не устанавливайте неофициальные сборки. OpenAI описывает установку и первый запуск в [Quickstart](https://learn.chatgpt.com/docs/quickstart).

### 2. Скачайте ZIP проекта и распакуйте его

1. Перейдите в опубликованный GitHub-репозиторий JobPilot. **Адрес репозитория будет внесен в это руководство перед выпуском:** `[URL репозитория JobPilot]`.
2. На странице репозитория выберите **Code → Download ZIP**.
3. В Проводнике создайте, например, папку `Документы\HomenSAI-JobPilot`.
4. Распакуйте ZIP в эту папку. Проверьте, что внутри видны `README.md`, `USER_GUIDE.md`, `AI_BUILD_SPEC.md`, `AGENTS.md`, `CLAUDE.md`, `TODO_FOR_AI.md` и `dashboard_template`.
5. Не распаковывайте архив в системную папку Windows и не переносите рабочую папку после настройки проекта без повторного указания нового пути Codex.

В распакованной папке будут храниться инструкции проекта и локальные рабочие данные. Личные профили, резюме, письма, OAuth-токены и статистика пользователя не должны публиковаться в GitHub.

### 3. Создайте локальный проект и укажите корневую папку

1. В Codex откройте раздел **Projects**.
2. Выберите добавление локального проекта/папки (**Add local project**, **Open folder** или аналогичную команду — название зависит от версии приложения).
3. Укажите полный путь к папке, куда распаковали проект, например `C:\Users\Имя\Documents\HomenSAI-JobPilot`.
4. Если вы уже создали проект, откройте меню проекта → **Edit project → Add folder**, выберите распакованную папку и затем **Make primary**.
5. Назовите проект, например **Поиск работы**.
6. Убедитесь, что в качестве основной указана именно папка с файлами JobPilot, а не отдельный файл и не родительская папка с посторонними данными.

Критически важно: простого сообщения в чате «работай по пути `…`» недостаточно. Папка должна быть фактически открыта/подключена как локальная папка проекта. Не создавайте только обычный ChatGPT Project без привязанной локальной папки. Официальная инструкция объясняет [локальные проекты и добавление папок](https://learn.chatgpt.com/docs/projects).

### 4. Создайте отдельный чат для настройки

1. Откройте созданный локальный проект.
2. Нажмите **New chat** внутри проекта.
3. Проверьте, что выбран **Codex** и локальное окружение компьютера (**Local / This computer**), а не Cloud или Worktree.
4. Назовите чат, например **Первичная настройка JobPilot**.

Чаты можно создавать отдельно для разных результатов: настройка, поиск, ежедневная проверка, месячный отчет. Файловая база проекта и журнал сохраняют состояние между чатами; не полагайтесь только на историю одного диалога.

### 5. Выставьте безопасные разрешения Codex

1. Внизу области ввода сообщения откройте меню разрешений.
2. Выберите **Ask for approval** («Запрашивать подтверждение»). Этот режим дает агенту доступ к текущей рабочей папке и запрашивает разрешение, когда действие выходит за установленную границу.
3. Если настройка недоступна, проверьте **Settings → General → Permissions**. Сам режим подтверждения обычно доступен; другие режимы можно включать только если это необходимо.
4. Не выбирайте **Full access**, не запускайте ChatGPT Desktop от имени администратора и не разрешайте агенту весь диск.
5. Если Codex запрашивает доступ за пределами папки проекта, остановитесь и проверьте, действительно ли это необходимо. Выдавайте только узкое разовое разрешение после понимания действия.
6. Интернет-поиск, файловый доступ, почта и управление экраном — отдельные возможности. Одно разрешение не открывает остальные автоматически.

Перед работой с локальными файлами еще раз проверьте имя проекта и открытую основную папку. Официальные пояснения: [режимы разрешений](https://learn.chatgpt.com/docs/permission-modes) и [песочница/границы доступа](https://learn.chatgpt.com/docs/sandboxing).

### 6. Выполните первый безопасный запуск

Вставьте в новый чат этот стартовый запрос:

```text
Работай только внутри открытой локальной папки HomenS.AI JobPilot.
Сначала подтверди фактический путь к рабочей папке и перечисли найденные файлы.
Прочитай README.md, USER_GUIDE.md, AGENTS.md, AI_BUILD_SPEC.md и DATA_CONTRACT.md,
затем найди TODO_FOR_AI.md.
Проверь, что пакет полный, и выполни только первый безопасный пункт плана.
Ничего не делай вне этой папки; не отправляй резюме и не меняй почту.
Если обязательного файла нет, не создавай его самовольно: сообщи, чего не хватает,
и задай только необходимые вопросы. Начальный режим — только подготовка черновиков.
```

В опубликованном релизе должны присутствовать `README.md`, `AGENTS.md` и `TODO_FOR_AI.md`. Если их нет, остановитесь: текущий набор документов — еще не готовый рабочий пакет. Агент должен показать план, запросить отсутствующие сведения и сохранить подтвержденные настройки в папке проекта.

### 7. Создайте свой профиль и добавьте сведения

1. Выберите или создайте отдельный профиль человека. Не объединяйте данные разных людей.
   Для нескольких направлений одного человека используйте тот же person_id: лимит 44 общий, не новый для каждого профиля.
2. Скопируйте исходное резюме и выбранные подтверждающие материалы в папку профиля `Локальные_данные\profiles\<profile_id>\source_documents\` либо заполните анкету, если релиз включает ее.
   До первого чтения этих файлов облачным агентом подтвердите передачу выбранных сведений его провайдеру. Локальное хранение не означает офлайн-обработку. Можно начать с обезличенного примера; файл анкеты сохраняется через явный экспорт, а не скрытую запись браузера.
3. Попросите агента извлечь факты и показать их для проверки. Подтвердите, исправьте или отклоните каждый сомнительный пункт. Агент не должен придумывать опыт, даты, сертификаты, уровень языка или достижения.
4. Выберите отдельно язык CV, сопроводительного письма/текста отправки и итогового отчета. Язык нельзя автоматически выводить из страны, города или языка интерфейса.
5. Если у вас есть шаблон отчета, положите его в локальную папку шаблонов профиля и укажите путь агенту. Оригинал не изменяется; отчет создается отдельной копией и остается нейтральным. Без шаблона будет сформирована простая таблица на выбранном языке с фамилией, именем и итогами заявок.
6. Укажите цель поиска, стартовую точку, радиус в километрах, транспорт (автомобиль и/или общественный транспорт), допустимое время дороги, желаемые города, расписание и исключения.
   Агент покажет выбранный часовой пояс, будние дни и проверенные региональные праздники. Для «через день» уточните, нужны календарные дни или каждый второй разрешенный рабочий день. Данные примера `examples/settings.example.json` сами по себе не являются вашими настройками.

Не помещайте секреты, пароли, коды подтверждения или OAuth-токены в файлы профиля. Проверьте, что `Локальные_данные/` исключена из публикации и синхронизации с публичным GitHub.

### 8. Подключите Gmail отдельно, если нужен почтовый учет

1. Сначала проверьте, что опубликованный релиз содержит точное название и адрес разрешенного Gmail-инструмента/сервера и перечень необходимых прав. Не угадывайте URL и не добавляйте случайный сервер.
2. Если релиз использует MCP-сервер, в ChatGPT Desktop откройте **Settings → MCP servers → Add server**, внесите только указанные в релизе параметры и сохраните. Если релиз использует подключаемое приложение, откройте соответствующую страницу Apps/Connectors.
3. Нажмите **Authenticate/Connect**, пройдите официальный OAuth-экран и перед подтверждением проверьте адрес Gmail.
4. Начните с чтения/поиска писем; право отправки подключайте отдельно, только если оно действительно нужно. Не разрешайте удаление, архивирование или изменение меток. Отправка по умолчанию остается `draft_only`.
5. Если система просит ввести пароль, одноразовый код или токен в чат, файл или репозиторий, откажитесь и остановите настройку.
6. Если требуемые права шире, чем описано в правилах проекта, не подтверждайте их и попросите объяснить ограничение.

Доступ к локальной папке и доступ Gmail настраиваются раздельно. Если нужный подключаемый инструмент или его официальные параметры не опубликованы, почтовая часть системы еще не готова к настройке: не подменяйте интеграцию случайным сервером. Общий официальный раздел Codex по [MCP и подключению OAuth-инструментов](https://learn.chatgpt.com/docs/extend/mcp).

### 9. Подготовьте и проверьте первую очередь

1. Попросите агента найти фирмы/вакансии в заданном радиусе и собрать источники, контакты, требования и дату проверки.
2. Проверьте карточки, дубликаты, адреса и актуальность вакансий. Для поездок проверьте выбранный способ передвижения и реальные маршруты.
3. Попросите подготовить подходящий пакет документов на выбранном языке, затем проверьте каждую дату, факт, получателя и вложение.
4. Просмотрите очередь и подтвердите даты/интервалы. Не включайте пакетную рассылку.
5. Лимит системы — не более 44 фактических подач резюме на человека за календарный месяц. Если остаток нельзя надежно проверить, агент должен остановиться.
6. Перед реальной отправкой сначала используйте режим черновиков. Отправка допустима только после настройки разрешенного профиля и проверки конкретного письма; защитные подтверждения почты нельзя обходить.

Если агент сообщил «исход отправки неизвестен», не поручайте просто отправить повторно: сначала требуется сверка SENT/подтверждения портала. При изменении вложения или получателя уже проверенное письмо проходит проверку заново. Тема по умолчанию — не более 50 символов с пробелами; это правило продукта, а не лимит почтового сервиса.

### 10. Включите управление экраном только при необходимости

Для поиска и ведения локальных файлов управление мышью обычно не требуется. Если отдельная задача действительно требует работать в браузере или другом окне:

1. В ChatGPT Desktop откройте **Codex → Plugins → Computer Use** и установите/включите компонент, если он доступен в вашей версии.
2. Откройте **Settings → Computer Use** и разрешите только нужное приложение.
3. На Windows держите управляемое окно видимым на активном рабочем столе.
4. Подтверждайте только понятные вам действия. Computer Use не заменяет OAuth, доступ к папке или согласие на отправку письма.

Текущий официальный порядок описан в разделе [Computer Use](https://learn.chatgpt.com/docs/computer-use). Эта возможность необязательна для базового сценария.

### 11. Ежедневная работа и расписание

Для ручной проверки откройте локальный проект, создайте чат **Ежедневная проверка**, попросите прочитать правила и выполнить текущий безопасный пункт плана. Агент обновит базу и журнал в папке, а затем создаст/обновит статистику.

Если в вашем приложении доступно расписание задач для локального проекта, сначала проверьте ручной запуск и затем попросите Codex создать повторяющуюся задачу с нужным временем и часовым поясом. Просмотрите ее текст и первый результат. Для локальных файлов компьютер должен быть включен, приложение запущено, папка доступна. Если расписание недоступно или ненадежно, запускайте проверку вручную. Актуальные ограничения описаны в [Scheduled tasks](https://learn.chatgpt.com/docs/automations).

Задача должна работать с той же основной папкой и журналом, не с отдельной копией/новым worktree без локальных данных. Пропущенные подачи отмечаются отдельно и перепланируются; они не отправляются автоматически пачкой после включения компьютера.

### 12. Откройте статистику и получите отчет

1. После проверки откройте `Локальные_данные\dashboard\index.html` — локальное меню профилей. Личная статистика находится в `dashboard\profiles\<profile_id>\index.html` внутри этого каталога данных. Сервер запускать не нужно.
2. Выберите год и месяц, отсортируйте таблицу по датам и используйте фильтры. Страница предназначена только для просмотра; изменения в базу вносит агент.
3. В конце отчетного периода попросите агента подготовить DOCX/PDF на выбранном языке и в выбранном шаблоне (если он есть).
4. Проверьте фамилию, имя, период, строки заявок, дату и краткую суть каждого ответа. Для заявки без ответа должен быть указан соответствующий перевод фразы «ответ не получен».
5. Отчет сохраняется локально и не отправляется по электронной почте автоматически.

В статистике различаются количество ответных писем и количество заявок с ответом. Ответ на старую заявку учитывается в месяце фактического получения. Если он пришел после формирования отчета, но в том же месяце, агент подготовит новую ревизию этого месяца. Если причина отказа не названа, так и пишется: «причина не указана».

На отдельной странице PDF помещается рыночная рекомендация с датой, радиусом, транспортом, проверенными источниками и охватом. Недоступные оценки помечаются явно; численность найденной выборки не выдается за точный размер рынка. Отчеты вашего профиля находятся в `Локальные_данные\profiles\<profile_id>\reports\<YYYY-MM>\`.

### 13. Обновление пакета и резервная копия

Перед обновлением скопируйте каталог `Локальные_данные/` в отдельную резервную папку. Скачайте новый ZIP в новую папку, сравните список версий и инструкций, а затем попросите агента перенести только подтвержденные пользовательские настройки. Не распаковывайте обновление поверх личных данных и не публикуйте `Локальные_данные/`.

## Если что-то не работает

- **Агент не видит файлы:** проверьте, что открыт локальный проект и его основная папка — именно распакованный корень. Одного пути в сообщении недостаточно.
- **Агент не может сохранить результат:** проверьте выбранный режим разрешений и доступ только к корню проекта; не включайте полный доступ ко всему диску.
- **Не удается подключить Gmail:** остановитесь, проверьте доступность официального коннектора и его права. Не вставляйте учетные данные в чат.
- **Не найден TODO/правила/шаблон статистики:** архив может быть неполным или это еще концептуальная сборка. Не поручайте агенту выдумывать отсутствующие файлы.
- **Не удается открыть статистику:** убедитесь, что агент создал личный `dashboard/profiles/<profile_id>/index.html`; чистый шаблон сам по себе не содержит ваших данных.
