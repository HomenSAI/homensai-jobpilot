## Область проверки этой редакции

### Кандидат 1.24.2 — исправления аудита ожидают проверки (12 октября 2026)

Кандидат остаётся в отдельной ветке до проверки и утверждения PR; слияние, выпуск и действия в Gmail в эту работу не входят. Исходный аудит выполнен на коммите `af55848c3b8c10925d92578c67ce3bb3a499b999` (1.24.1). Шесть дефектов ниже воспроизведены на искусственных данных; гонка релиза показана локальной Git-моделью, без публикации выпуска.

| ID | Воспроизведение на исходной версии | Результат кандидата |
|---|---|---|
| JP-001 | Проверка приватности проверяет A; перед скачиванием релиза появляется новый main B | Оба задания используют SHA события. Локальная модель сохраняет A, а B не проходит проверку |
| JP-002 | `sent_at` и история содержат `2026-02-30T10:00:00Z` | Отказ без переноса на 2 марта. Допустимые високосные даты и смещения ISO работают |
| JP-003 | `thank_you_sent_at` в 2030, а `generated_at` в 2026 | Отказ; завершённое событие из будущего не показывается как Sent. Будущие планы и встречи допустимы |
| JP-004 | При статусе черновика сохранены `sent_at` и история до отправки | Отказ; согласованность статуса с отправкой и границы истории проверяются отдельно |
| JP-005 | `archive.folder_href` равен `//example.com/` или выходит из пакета | Отказ; допустим только `Local_Data/Archive/` этого пакета, в том числе на локальных `file:`-страницах профиля |
| JP-006 | `summary.js` присваивает корректные данные, затем выбрасывает исключение | Статистика скрыта, показана диагностика |

**Доказательства:** пройдено 88/88 синтетических проверок в JavaScript VM и Microsoft Edge без окна: исходные ошибки, четыре языка интерфейса, поиск, сброс примера, ширина 390 px и 28 страниц руководства. Проверены 6 файлов JavaScript, 7 встроенных скриптов, 4 файла JSON, 40 записей JSONL и 1 334 локальные ссылки. Точный Bash-код проверки приватности принял чистый искусственный коммит и отверг запрещённый искусственный путь; исправленный релиз выбрал проверенный SHA. Инструменты аудита и исходные результаты остаются вне пакета, в который не добавляются скрипты. Независимый ИИ также выполнил 43/43 проверки валидатора и одобрил основные исправления; окончательная проверка PR всё ещё обязательна.

**Запрос проверяющему:** прочитать diff и таблицу; проверить календарные даты, срез данных, статус черновика и факт отправки, разрешение ссылок архива на HTTP и локальных страницах профиля, обработку ошибки скрипта и совпадение SHA проверки с релизом. Убедиться, что правильные снимки работают. Явно утвердить изменения либо перечислить исправления до любого слияния в `main`. Не использовать реальные Gmail и личные записи для проверки кандидата. Исторический обзор ниже сохранён и не описывает эти новые проверки.

Что запускалось, кем и чем — до этой версии включительно. Ни одна из проверок не использовала настоящий аккаунт Gmail, настоящего работодателя, Codex или собственный Claude Code пользователя.

- **Исполняемая модель правил** (`examples/simulation/SIMULATION_REPORT.md`): тестировщик реализовал письменные правила как одноразовую модель с имитированным почтовым ящиком. Прошли 46 проверок: пять заявок с ответами, отказ, недоставка и ошибка почты, двойная отправка, лимиты, два чата, прерванная работа. Найдены и исправлены два противоречия в правилах (1.17.1).
- **Пробные прогоны первой настройки**: агент Claude в изолированной копии пакета следовал `CLAUDE.md`, `AGENTS.md` и `TODO_FOR_AI.md` для трёх вымышленных людей (ничего не подготовлено; папки заполнены; длинный голосовой рассказ) до этапа `ready`. Их находки внесены в 1.18.0. Для конвертации и рендера шаблонов там использовался LibreOffice.
- **Страница статистики**: открыта в Microsoft Edge без интерфейса (headless) на русском и немецком (блок стоимости времени, полосы квоты); ранее — проверки валидатора снимка (18 в JavaScript VM). Вёрстка на телефонах, работа с клавиатуры и печать не проверялись.
- **Шлюз приватности**: `.github/workflows/privacy-gate.yml` запускался локально на чистой копии (прошёл) и на копии с подложенными персональными данными (не прошёл, как и ожидалось); на GitHub он ещё не запускался.
- **Не запускалось**: Codex; Claude Code пользователя; настоящий Gmail (чтение, подтверждение в «Отправленных» и «Запланированных», вложения); Word; реальные пользователи; запланированные задачи.

## Где сейчас проект

**В этом выпуске:** двуязычные рабочие процедуры; обновлённые README, история создания и отдельные уведомления лицензий кода/документации; расширенный контракт журнала и расписаний; исправления проверки снимка статистики, исторических итогов, пустого месяца, общей квоты и сортировки результатов.

**Проверено в этой рабочей копии:** 18 целевых проверок страницы статистики в JavaScript VM прошли, включая повреждённые снимки, дубликаты ID ответов, поздние ответы, выбор пустого месяца, отсутствие общего счётчика квоты и сортировку технических ошибок. Это не полная проверка браузера или цикла агента/Gmail. Эти проверки относятся к более ранней рабочей копии (1.5.1).

**Среда разработки:** проект разрабатывался, локально проверялся по записям и виртуально проверялся в среде **Codex**. **Anthropic / Claude Code в этом цикле не тестировался**; совместимость не подтверждена. Проверки в Codex не являются полной сертификацией проекта, а независимая полная приёмка исходного агента остаётся незавершённой.

**Ещё не пройдено:** полная ручная приёмка работы агента; настройка Codex/Claude Code на пользователе; реальное планирование Gmail и обработка ответов; рендер DOCX через Word; первый запуск workflow выпуска и шлюза приватности на GitHub. Реальная почта, работодатели и внешние AI API не подключались.

В рабочем процессе намеренно нет отдельного приложения для поиска и рассылки. Страница статистики содержит HTML/CSS/JavaScript для проверки, сортировки, фильтрации и показа снимка, подготовленного агентом. Согласие, квота и внешняя почта остаются процедурными правилами, а не техническими замками. В версиях 1.2–1.4 были созданы двуязычная архитектура, журнал на человека и инструкции агента; версия 1.5 расширяет месячный цикл, сверку Gmail, локальные архивы, отчёты, лицензирование и проверку статистики.

Обзор охватил AI_BUILD_SPEC.md, HTML-обзор и руководство пользователя. Личные архивы, Gmail и существующие заявки не затрагивались. Код просмотренных GitHub-аналогов не использовался. Обзор проверяет согласованность проекта; это не аудит внешних сервисов и не исследование рынка труда.

| Не было входного README; старт требовал несуществующих файлов | README перечисляет реально существующие файлы и отделяет документальную сборку от будущего релиза |
| Формат базы оставался открытым | JSON/JSONL без SQL; DATA_CONTRACT задаёт идентификаторы, пути, главные записи и проекции |
| Спецификация делила отчёты и логи, а HTML хранил их внутри профилей | Отчёты и логи относятся к профилю; квота — к человеку |
| Для «атомарной квоты» нет отдельного исполнительного механизма | Описаны правило одного писателя, резерв, ID действий и восстановление; это процедурная защита, не техническая блокировка |
| Неопределённая отправка могла вызвать дубль | `send_uncertain` удерживает резерв и требует сверки по доказательствам вместо слепого повтора |
| Ответ, доставка и благодарность могли слиться в один статус | У подачи, доставки, исхода и последующих действий отдельные состояния |
| «Ответы» могли означать письма или заявки | Раздельные счётчики событий-ответов и заявок с ответом, включая поздние ответы |
| Отчёт в последний рабочий день мог пропустить поздние ответы | Манифесты, ревизии и отнесение к месяцу фактического получения |
| Анализ рынка стал необязательным | Отдельная страница рынка снова обязательна; при недоступности источников пишется «оценка недоступна» |
| «Локальное» хранение можно было принять за «без передачи в облако» | Согласие даётся до того, как облачный агент прочитает личные оригиналы; экспорт анкеты — явное действие |
| Статический файл казался способным заметить позднюю неудачную проверку | Указаны идентификаторы снимков, время обновления и то, что устаревшая страница реально может показать |
| В публичных документах были частные примеры прежних разрешений | Заменены общей политикой импорта, которая никогда не включает разрешения автоматически |
| В HTML были разные версии, а заполнители имён файлов разбирались как теги | Версии синхронизированы, заполнители экранированы, добавлена навигация |
| Обзор был одной очень длинной страницей | Разбит на короткие страницы с меню; добавлена страница статистики |
| Порядок установки (что сначала — агент или архив) был неясен | В руководстве объяснён порядок: агент, потом архив, потом соединение; в каждом шаге написано, что должно появиться на экране |
| Готовность выражалась только общими намерениями | Конкретные сценарии приёмки со входными данными и ожидаемым результатом |

## Неизменные решения

Название продукта — **HomenS.AI JobPilot**, репозиторий — `homensai-jobpilot` ([HomenSAI/homensai-jobpilot](https://github.com/HomenSAI/homensai-jobpilot)). Авторство и визуальный стиль (как у homensai.com и HomenS.AI Core) сохраняются. Нужны агент и папка; Docker не используется; HTML-страница только показывает данные; лимит — 44 отправки на человека в месяц. Ближние цели идут первыми, CV и письма персональные, языки независимы, отчёты нейтральные, почтовые действия требуют отдельного согласия, код просмотренных аналогов не используется.

## Статус возможностей (R09)

Каждая возможность отмечена одной из трёх меток: **проверено в тестах** (есть записанная проверка, её объём указан), **описано, не проверялось на практике** (написано в инструкциях, записанного прогона нет) или **недоступно** (платформа или пакет этого не предоставляют). Ни одна возможность не отмечена как проверенная на практике без записанного прогона.

|---|---|---|

## Что ещё не проверено или не реализовано

- Рабочие инструкции ещё не прошли полную приёмку на реальном пользователе Codex или Claude Code. Пакет остаётся экспериментальным; сценарии следует выполнить в чате на синтетических данных.
- Возможности Gmail-коннектора и встроенного браузера необходимо отдельно проверить в установленном аккаунте: чтение целой цепочки, Gmail «Запланированные», вложения, подтверждение в «Отправленных» и восстановление после прерывания. В ходе этого обзора к реальному Gmail не подключались.
- Полный цикл создания DOCX/PDF и визуальная проверка каждой страницы в Word или LibreOffice агентом не испытаны.
- Полная пошаговая настройка Claude Code не написана; подробное руководство рассчитано на Codex в Windows.
- Workflow выпуска и шлюз приватности (`.github/workflows/privacy-gate.yml`) ещё должны пройти первый запуск на GitHub. Ручной контрольный список выпуска остаётся.
- Общий лимит 44 заявки на человека в месяц, согласия, работа с Gmail, расписание, архивы и доставка отчётов описаны процедурами, а не жёсткой блокировкой или гарантированной фоновой службой.
- Ежедневный отчёт пользователю через Gmail (R08), сведения о ценах и тарифах (проверены по официальной странице тарифов 8 октября 2026; с тех пор не перепроверялись) и двусторонний разбор документов (R19) требуют записанного прогона, прежде чем их можно назвать проверенными.
- Нейтральные шаблоны резюме, сопроводительного письма и отчёта есть только на английском и украинском; немецких и русских нет.

`.gitignore`, пример настроек и шаблон статистики можно проверить локально, но они не доказывают работоспособность процесса агента. Сценарии агента не помечаются PASS без записанной ручной проверки и доказательств.
