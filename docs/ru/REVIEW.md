# HomenS.AI JobPilot — обзор и статус

[English](../../REVIEW.md) | [Русский](REVIEW.md)

07.10.2026 · Автор идеи и разработчик: Serhii Khomenko / HomenS.AI · [homensai.com](https://homensai.com/) · CC BY-NC 4.0

## Где сейчас проект

**Готово:** спецификация, архитектура, контракт данных и сценарии приёмки (на английском и русском); черновики инструкций для агента (`AGENTS.md`, `CLAUDE.md`, `TODO_FOR_AI.md`); готовые папки для материалов человека и формат базы знаний; иллюстрированный обзор с меню и страница пошаговой установки; страница статистики с годами, месяцами и днями, сортировкой по дате и результату и фильтрами (работает на примерах данных); нейтральный пример настроек; лицензия.

**Ещё не сделано:** проверка файлов инструкций на практике (Codex и Claude Code, на человеке, который ничего не подготовил, на человеке, который заполнил папки, и на голосовом интервью); проверка подключения Gmail; прохождение сценариев приёмки вручную; реальные данные на странице статистики.

**Программного кода нет**, и он не планируется: ИИ-агент следует записанным правилам и ведёт обычные файлы. Версия 1.2 добавила ARCHITECTURE.md, двуязычную структуру (английский в корне, русский в `docs/ru`) и один журнал на человека для событий квоты и заявок. Версия 1.3 убрала из замысла локальные команды, скрипты и модули: журнал, лимит и восстановление — порядок действий, которому следует агент, и документы прямо говорят, что это не технические замки. Версия 1.4 добавила файлы инструкций, с которыми агент начинает сам, готовые папки для материалов человека, базу знаний (один файл с жизнеописанием человека в виде подтверждённых фактов) и интервью голосом или текстом вместо формы, а также согласовала файлы для ИИ с HTML-страницами и руководством.

Обзор охватил AI_BUILD_SPEC.md, HTML-обзор и руководство пользователя. Личные архивы, Gmail и существующие заявки не затрагивались. Код просмотренных GitHub-аналогов не использовался. Обзор проверяет согласованность проекта; это не аудит внешних сервисов и не исследование рынка труда.

## Найденные пробелы и исправления

| Пробел | Исправление |
|---|---|
| Не было входного README; старт требовал несуществующих файлов | README перечисляет реально существующие файлы и отделяет документальную сборку от будущего релиза |
| Формат базы оставался открытым | JSON/JSONL без SQL; DATA_CONTRACT задаёт идентификаторы, пути, главные записи и проекции |
| Спецификация делила отчёты и логи, а HTML хранил их внутри профилей | Отчёты и логи относятся к профилю; квота — к человеку |
| «Атомарная квота» не имела механизма | Поскольку программы нет, записанный порядок действий: файл-метка единственного писателя, строка резерва до вызова, идентификаторы действий и восстановление; документы прямо говорят, что это порядок, а не технический замок |
| Неопределённая отправка могла вызвать дубль | `send_uncertain` удерживает резерв и требует сверки по доказательствам вместо слепого повтора |
| Ответ, доставка и благодарность могли слиться в один статус | У подачи, доставки, исхода и последующих действий отдельные состояния |
| «Ответы» могли означать письма или заявки | Раздельные счётчики событий-ответов и заявок с ответом, включая поздние ответы |
| Отчёт в последний рабочий день мог пропустить поздние ответы | Манифесты, ревизии и отнесение к месяцу фактического получения |
| Анализ рынка стал необязательным | Отдельная страница рынка снова обязательна; при недоступности источников пишется «оценка недоступна» |
| «Локальное» хранение можно было принять за «без передачи в облако» | Согласие даётся до того, как облачный агент прочитает личные оригиналы; экспорт анкеты — явное действие |
| Статический файл казался способным заметить позднюю неудачную проверку | Указаны идентификаторы снимков, время обновления и то, что устаревшая страница реально может показать |
| В публичных документах были частные примеры прежних разрешений | Заменены общей политикой импорта, которая никогда не включает разрешения автоматически |
| В HTML были разные версии, а заполнители имён файлов разбирались как теги | Версии синхронизированы, заполнители экранированы, добавлена навигация |
| Обзор был одной очень длинной страницей | Разбит на короткие страницы с меню; добавлена страница статистики |
| Порядок установки (что сначала — агент или архив) был неясен | В руководстве объяснён порядок: агент, потом архив, потом соединение; в каждом шаге написано, что должно появиться на экране |
| Готовность выражалась только общими намерениями | Конкретные сценарии приёмки со входными данными и ожидаемым результатом |

## Неизменные решения

Название продукта — **HomenS.AI JobPilot**, репозиторий — `homensai-jobpilot` ([HomenSAI/homensai-jobpilot](https://github.com/HomenSAI/homensai-jobpilot)). Авторство и визуальный стиль (как у homensai.com и HomenS.AI Core) сохраняются. Нужны агент и папка; Docker не используется; HTML-страница только показывает данные; лимит — 44 отправки на человека в месяц. Ближние цели идут первыми, CV и письма персональные, языки независимы, отчёты нейтральные, почтовые действия требуют отдельного согласия, код просмотренных аналогов не используется.

## Оставшиеся этапы (ни один из них пока не работает)

- Проверка `AGENTS.md`, `CLAUDE.md` и `TODO_FOR_AI.md` на практике и исправление того, что агенты поняли неверно.
- Шаблоны документов (CV, сопроводительное письмо) в виде инструкций для агента.
- Выбор и проверка конкретного подключения к Gmail и его точных параметров.
- Полная пошаговая настройка для Claude Code; руководство по установке сейчас подробно описывает Codex на Windows.
- Прохождение сценариев приёмки вручную: восстановление почты, общий лимит, прерванная работа, два чата одновременно.
- LICENSE-DOCS, NOTICE и проверка прав на все файлы выпуска.

`.gitignore`, JSON-пример и шаблон статистики полезны уже сейчас, но не показывают, что система работает. Сценарии не отмечаются как PASS без записанной ручной проверки и доказательств.

## Выполненные проверки

7 октября 2026 ссылки в Markdown, HTML-страницы и JSON-пример проверены локальными средствами (разборщики HTML и JSON, браузер без интерфейса): ссылки между документами ведут на существующие файлы, повторяющихся идентификаторов HTML нет, страницы не загружают внешние ресурсы, а пример настроек — корректный JSON с ожидаемыми значениями по умолчанию (`draft_only`, лимит 44, лимит темы 50, обязательная страница рынка, исключённые выходные, непроверенные праздники, нет почтового аккаунта и согласия). Страница статистики открыта в браузере в ширине компьютера и телефона: работают сортировки, фильтры, оба языка, светлая и тёмная темы и кнопка «Top», сетевых запросов страница не делает. Эти проверки касаются структуры документов и страницы статистики. Внешние адреса и будущая функциональность продукта не проверялись.
