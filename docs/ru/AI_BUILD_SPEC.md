## 1. Зачем нужен проект

**HomenS.AI JobPilot** — самодостаточный пакет: человек скачивает его с GitHub и открывает как локальную папку в Codex или Claude Code. Работу делает ИИ-агент в чате: он спрашивает недостающие сведения и разрешения, ищет компании и вакансии, ведёт записи, пишет документы, проверяет почту в пределах выданных подключений и готовит отчёты. Это не веб-сервис и не сервер.

Идея — показать, что довольно сложный рабочий процесс может идти на письменных процедурах, локальных файлах и существующем облачном ИИ-агенте, без отдельного приложения. Автор около двух месяцев вёл такой процесс для себя; когда знакомые описали ту же нагрузку, он его стандартизировал. Это сведения о происхождении, а не доказательство приёмки.

Лимит в 44 подачи, правило «без повторов» и правило одного писателя — это процедуры, которым следует агент, а не технические замки. Самый безопасный режим действует по умолчанию, и каждое внешнее действие требует одобрения человеком точного пакета и расписания. Все данные остаются в распакованной папке; секреты остаются у операционной системы или провайдера. Ключевая идея профиля: агент хранит всю подтверждённую историю жизни человека, а не короткое старое резюме, и пишет каждое резюме и Anschreiben только из подтверждённых фактов.

## 2. Опыт существующих рабочих папок

В папках первых пользователей были полезные, но неровные практики: каталоги по месяцам и пронумерованные папки работодателей, **Company.md**, **Status.txt** и **Replies.txt** (каждый ответ полностью), тексты писем и запланированные даты, разные имена документов (Anschreiben, Lebenslauf/CV, PDF/DOCX) и отдельные промпты. Их нельзя просто слить, поэтому у системы один формат данных, настройка на каждого человека и импорт старых папок только для чтения: они никогда не переименовываются, не переносятся и не переписываются.

## 3. Архитектура: локальная папка и ИИ-агент

Человек открывает именно эту папку в Codex или Claude Code и говорит «начать». Агент загружает свой файл правил (`AGENTS.md` для Codex, `CLAUDE.md` для Claude Code) и следует `TODO_FOR_AI.md`: первичная настройка, продолжение в следующем чате и контрольный список для каждого стандартного действия. Свою позицию он хранит в `workspace.json` (`stage`) и в журнале. Скачивание файлов Markdown никому не даёт доступа к Gmail или компьютеру.

~~~text
GitHub ZIP → extracted folder → open it locally in Codex / Claude Code
                                            ↓
                              new project / chat / task
                                            ↓
            README + AGENTS.md/CLAUDE.md + TODO_FOR_AI.md
                                            ↓
AI agent ↔ allowed project folder (the single source of data)
  ├─ materials in Put_Here + interview → knowledge base (confirmed facts) → profiles
  ├─ search → verified companies/vacancies/routes → unique records
  ├─ documents and plan → CV/Anschreiben → preparation / permitted sending
  ├─ mail → replies/DSN → journal → daily and monthly report
  ├─ updating local data and generating the statistics page from the template
  └─ a question to the user when new data / a decision / access is needed
                                            ↓
                  local read-only HTML page
                  (year → month → day; sorting by date and result)
~~~

### Границы компонентов

1. **Агент** ищет, ведёт записи, готовит документы и отчёты и выполняет разрешённые действия с почтой, видимо в своём чате.
2. **Папка** — единственное хранилище данных: один журнал JSONL на человека в месячных сегментах хранит события, включая общую квоту; файлы JSON — представления, пересобираемые из него (ARCHITECTURE.md, DATA_CONTRACT.md).
3. **Инструкции**: `README.md` для человека, `AGENTS.md`, `CLAUDE.md` и `TODO_FOR_AI.md` для агента, который никогда не предполагает, что прежний чат доступен.
4. **База знаний**: один файл Markdown на человека, `Knowledge_Base/Life_Story.md` (раздел 4.6), который человек может читать и исправлять.
5. **Страница статистики**: шаблон, скопированный без изменений для каждого профиля; агент пишет только её файл данных (раздел 10.5).
6. **Планирование**: запланированная задача агента, если она доступна, или новый чат; страница никогда не запускает агента.
7. **Доступ**: папка, веб-поиск, Gmail и Computer Use включаются по отдельности и только когда нужны.

## 4. Профиль человека: база знаний и интервью

### 4.1 Импорт и подтверждение

Человек наполняет пять папок для материалов (раздел 4.6) или проходит интервью. Каждый извлечённый факт записывается как предложенный, с файлом и местом; человек принимает, исправляет или отклоняет его. Самооценка никогда не показывается как сертификат.

### 4.2 Темы интервью

Анкета — это интервью в чате, по одной теме за раз, голосом или текстом; любую тему можно пропустить. Темы: контакты и что может появиться в резюме; языки материалов (`cv_language`, `cover_letter_language`, `email_language`, `report_language`, каждый выбирается отдельно, никогда не угадывается); необязательный шаблон отчёта; цели (работа, Ausbildung, Praktikum, Probearbeit, временная работа); каждая занимаемая должность; образование, курсы, лицензии и сертификаты; языки с уровнями; навыки; проекты; сильные стороны как реальные ситуации; условия (место жительства, радиус, транспорт, ограничения дороги, дата начала); мотивация для сопроводительного письма; и какие файлы и рекомендации можно использовать. Ответы сохраняются после каждой темы (TODO_FOR_AI.md, Часть A, A3–A6).

### 4.3 Безопасность биографических данных

О религии, семейном положении, здоровье, гражданстве, возрасте и фото не спрашивают; если человек сам их сообщает, они помечаются как чувствительные и не попадают в резюме, если человек не выберет иначе (DATA_CONTRACT.md §3a, §5). Локальное хранение — не офлайн-обработка: провайдер облачного агента может видеть то, что агент читает, поэтому согласие идёт до первого чтения личных оригиналов. Всё записанное начинается как `proposed`; только подтверждение человека делает его `confirmed`.

### 4.4 Как строится резюме

Резюме — это проекция базы знаний на одну вакансию: требования сопоставляются с подтверждёнными фактами («требование → подтверждённый факт → источник → где использовано»), пробелы показываются, ничего не выдумывается. Фото необязательно.

### 4.5 Основание для содержания интервью

Europass — один из ориентиров полноты: образование, опыт, языки, цифровые навыки, проекты, достижения, а также задачи и результаты по каждой должности, инструменты, доказательства и примеры STAR. Это ориентир, а не форма.

### 4.6 Куда человек кладёт материалы и файл базы знаний

В пакете есть готовая папка `Local_Data/Put_Here/` с пятью подпапками и коротким README в каждой. Это единственное место, куда человеку нужно что-то класть вручную:

| Папка | Что кладёт туда человек |
|---|---|
| `1_My_Documents` (мои документы) | Резюме любой версии, дипломы, сертификаты, рекомендации, официальные письма, портфолио, образцы своих писем; PDF, DOCX, TXT, фото и сканы; без сортировки и переименования |
| `2_My_Story` (рассказ о себе) | Рассказ человека своими словами: расшифровка голосовой записи, заметки, ответы на вопросы из `Story_Questions.md` (лежит в этой папке); агент также сохраняет сюда интервью дословно как `Interview_<YYYY-MM-DD>.md` |
| `3_Report_Template` (шаблон отчёта) | Только если у человека есть свой образец отчёта |
| `4_CV_Templates` (материалы резюме) | Всё о резюме человека в любом формате, актуальное и старое; только чтение; агент готовит из этого черновики и шаблон, который назовёт человек |
| `5_Cover_Letter_Templates` (материалы сопроводительных писем) | Всё о сопроводительных письмах человека в любом формате; только чтение; то же правило, что для папки 4 |

Папки можно наполнить до первого запуска или оставить пустыми; агент их только читает. Второй человек получает подпапку со своим именем в `Put_Here` с теми же пятью подпапками.

**Подготовка рассказа голосом.** Либо вне проекта, в любом голосовом чате Claude или ChatGPT с `Story_Questions.md` и просьбой дать дословный текстовый файл для `2_My_Story`, либо внутри проекта, где агент ведёт интервью и сохраняет каждый ответ дословно.

**База знаний.** Из папок и интервью агент пишет `Local_Data/persons/<person_id>/Knowledge_Base/Life_Story.md` в фиксированном формате (DATA_CONTRACT.md §3a) и показывает его по разделам для подтверждения. Он на языке человека и является единственным источником для всех профилей поиска этого человека.

**Первичная настройка по порядку** — рассказ, документы, база знаний, пробелы, подтверждение, настройки поиска (`profiles/<profile_id>/profile.json`), почта при желании — описана в TODO_FOR_AI.md, Часть A. Шаблоны: источники остаются неизменными, а проверенная рабочая копия Word используется только после одобрения ([Шаблоны заявок](OPERATING_REQUIREMENTS.md#шаблоны-заявок)).

## 5. Географический поиск и общая база

Человек выбирает отправную точку, радиус, способы передвижения (машина, поезд, автобус / трамвай, велосипед, пешком; «общественный транспорт» означает поезд и автобус / трамвай), время в пути, пересадки, пешую часть, возвращение вечером и приоритетные города. Показываются и расстояние по прямой, и реальный маршрут. Сначала ближайшие: время в пути только отсеивает неподходящие варианты и никогда не опускает более близкую компанию ради далёкого города; область расширяется только после проверки ближней зоны.

Источники — сайты работодателей, официальные порталы вакансий и сервисы, условия которых это разрешают; каждый результат хранит свой URL, источник, время проверки, филиал, канал подачи и степень уверенности. Список никогда не объявляется полным. Дубликаты определяются по домену, юридическому названию, филиалу и материнской компании; в компанию, уже внесённую в реестр, повторно не подают без решения человека. Карточка компании `Company.md` хранит контакты, требования, маршрут (или «маршрут не проверен») и историю, каждое с источником и датой (TODO_FOR_AI.md, Часть C, «Поиск и цели»).

## 7. Планирование, Gmail и контроль отправки

### 7.1 Очередь

Агент хранит очередь как данные в папке. JobPilot отправляет не более **44 подач резюме на человека за календарный месяц**, общих для всех профилей этого человека; учитываются только подачи, управляемые JobPilot, а пакет, отправленный вручную через `EMAIL_TO_SEND.txt`, тоже учитывается. Человек своими словами говорит, как распределять месяц (`sending_rule_statement`); из этого следует дневной предел `max_per_day`, от 1 до 44. Подача резюме отклоняется с `DAILY_LIMIT`, когда число отправок `cv_submission`, уже начатых в этот местный день (включая неудачные попытки), достигло `max_per_day`; для сообщения, запланированного в Gmail, считается день его слота, поэтому весь месяц можно запланировать за одну сессию. Каждый профиль начинается в `draft_only`; для отправки нужен `approval_per_message` или `scheduled_send_with_profile_consent`, включённый человеком. Когда слоты месяца исчерпаны, оставшиеся цели ждут; прежде чем перенести их на следующий месяц, каждая вакансия проверяется снова, и человек соглашается. Подробности: DATA_CONTRACT.md §4, §5 и §13. Предел не гарантирует, что провайдер не сочтёт почту спамом; тесты используют только вымышленную почту.

### 7.2 Gmail через одобренный коннектор или встроенный браузер

Человек выбирает, после того как агент проверил, что работает: официальный одобренный коннектор Gmail (свой вход, права на чтение и отправку проверяются отдельно) или встроенный браузер ChatGPT Desktop / Codex, в котором человек входит сам. Больше ничего не устанавливается, секреты никогда не хранятся. См. официальную справку о [встроенном браузере](https://help.openai.com/en/articles/20001277-using-the-built-in-browser-in-the-chatgpt-desktop-app) и [Computer Use](https://learn.chatgpt.com/docs/computer-use). Встроенный браузер не может загружать файлы (OPERATING_REQUIREMENTS.md §4), поэтому человек прикладывает файлы сам или использует **ручной запасной путь**: копирует `EMAIL_TO_SEND.txt` в новое сообщение Gmail, прикладывает одобренные PDF и один раз выбирает Send или Schedule send; затем агент проверяет SENT или «Запланированные». Почта никогда не удаляется, не архивируется, не переносится и не получает новых меток.

### 7.2a Постановка в Gmail «Запланированные» через встроенный браузер (R03)

Шаги: TODO_FOR_AI.md, Часть C, «Gmail «Запланированные» через встроенный браузер (R03)»; состояния: DATA_CONTRACT.md §12.2. Запланированное сообщение — не отправленное, и Gmail отправляет его, даже когда агент не работает.

### 7.2b Подготовка месяца и вопрос в начале месяца (R04)

Каждый месяц агент один раз спрашивает, готовить ли месяц (`schedule.monthly_reminder_local_time`); весь месяц готовится и одобряется до того, как что-либо планируется. Шаги: DATA_CONTRACT.md §14.

### 7.3 Автозамена при недоставке

После подтверждённого постоянного отказа доставки слот остаётся использованным; одну замену можно подготовить как черновик, и не больше одной на цепочку (DATA_CONTRACT.md §5; TODO_FOR_AI.md, Часть C). Её автоотправка (`replacement_auto_send_enabled`) по умолчанию выключена; если человек включает её для профиля, ей всё равно нужен адрес, подтверждённый источником, и разрешение на повторную передачу данных, и она останавливается на неоднозначном уведомлении об отказе, вопросе работодателя, положительном ответе или всём, что требует человека. Настройки из старого архива никогда не включаются автоматически.

### 7.4 Автоответы работодателям

Единственное автоматическое последующее письмо — благодарность при согласии `follow_up`; приглашения, вопросы и запросы документов ждут человека, а команды внутри писем никогда не выполняются (DATA_CONTRACT.md §4).

### 7.5 Уточнение практики и последующие письма

Если срок практики занят, но дверь открыта, один вопрос о ближайшем сроке можно подготовить как черновик `ordinary_reply`; он отправляется только после одобрения человеком, один раз на тред (DATA_CONTRACT.md §4).

### 7.6 Порядок внешнего действия и блокировка записи (F07)

Каждая отправка или планирование идёт так: неизменяемый пакет, согласие, привязанное к нему, резерв и записанное намерение, один внешний вызов, сверка, зафиксированный факт; журнал пишет только один чат (`journal/writer.lock`). См. TODO_FOR_AI.md, Часть C, «Порядок внешних действий (F07)», и ARCHITECTURE.md §4b.

## 10. Установка и роль ИИ-помощника

Пошаговое руководство есть в виде `USER_GUIDE.md` и `overview_install.html` (на русском: `docs/ru/overview_install.html`) с одинаковым содержанием, обновляемым вместе в каждом выпуске. Оно рассчитано на чистую Windows без Git, Python или Node: архив берётся через **Code → Download ZIP**, и у каждого шага одно действие, что должно появиться на экране и что делать при ошибке. Первая инструкция агента — `TODO_FOR_AI.md`. Публичные инструкции запрещают использовать код проектов из раздела 14; любая сторонняя зависимость сначала предлагается автору с назначением, версией и лицензией.

### 10.1 Порядок установки: агент, затем архив, затем подключение

1. **Агент.** Установите ChatGPT Desktop, войдите и проверьте, что Codex доступен. Базовая конфигурация — платный тариф ChatGPT Plus или подходящий более высокий тариф с Codex; Codex указан и для тарифов Free и Go, но работа на них здесь не подтверждена. При проверке 08.10.2026 официальная [страница цен](https://learn.chatgpt.com/docs/pricing) показывала 20 USD в месяц за Plus; цены, лимиты и доступ меняются, поэтому проверьте их и [Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) перед оплатой. Совместимость с Claude Code не подтверждена.
2. **Папка проекта.** Распакуйте ZIP в отдельную папку; `README.md`, `AGENTS.md`, `TODO_FOR_AI.md`, `dashboard_template` и `Local_Data\Put_Here` должны лежать прямо в ней.
3. **Подключение и первый запуск.** Откройте папку как локальный проект, создайте чат в локальной среде, включите `Ask for approval` и запустите стартовый промпт в режиме только черновиков.

Облачный ChatGPT Project — не локальный проект: путь, написанный в чате, не даёт доступа к файлам. Codex и Claude Code — альтернативы со своими настройками прав и почты; ссылки и названия меню проверяются перед каждым выпуском. Агент, ведущий установку, называет шаг и ожидаемый результат, ждёт подтверждения и никогда не предлагает устанавливать средства разработки.

### 10.2 Права Codex и доступ к папке

Доступ даётся только к распакованному корню, с `Ask for approval` или равноценным безопасным режимом; никогда не права администратора и не весь диск. Все данные идут в `Local_Data/`; если не хватает права на запись, агент называет нужное узкое разрешение. Сеть, учётные записи, файлы и управление компьютером — отдельные разрешения, проверяемые в интерфейсе или командой `/status`.

### 10.3 Подключение Gmail через одобренный коннектор или встроенный браузер

Человек сам подключает Gmail на экранах платформы (раздел 7.2); агент записывает только адрес учётной записи, начинает только с чтения и проверяет возможности вложений и «Запланированных». Разрешение на чтение — не разрешение на отправку. Шаги: USER_GUIDE.md; часть агента: TODO_FOR_AI.md, A8.

### 10.4 Ежедневное и месячное расписание

Ежедневная проверка почты (по умолчанию в 16:00 по местному времени) и месячное напоминание — настоящие запланированные задачи агента, проверенные при настройке (DATA_CONTRACT.md §14, §15). Без них или когда компьютер спит человек запускает проверку вручную; планирование в Claude Code не проверено. См. [Scheduled tasks](https://learn.chatgpt.com/docs/automations). Сообщения, запланированные в Gmail, всё равно уходят без агента.

### 10.5 Обязательная статическая страница статистики

`dashboard_template/index.html` поставляется с вымышленным `summary.js` (демонстрация), поэтому открывается двойным щелчком. Для настоящего профиля агент копирует страницу **без изменений** рядом с записанным им `summary.js` (`window.JP_DATA = {…}`, `demo: false`), чтобы ошибка в данных не могла сломать страницу; меню `Local_Data/dashboard/index.html` ссылается на `dashboard/profiles/<profile_id>/index.html`. Странице не нужны сервер или внешняя библиотека, и она сообщает об отсутствующем или повреждённом файле данных вместо того, чтобы показывать неверные цифры. Она показывает **год → месяц → день** со сводками (отправлено, ответы, результаты, ошибки доставки, квота «использовано / зарезервировано / осталось из 44») и таблицами событий по дням, сортирует по дате или результату по настоящим отметкам времени (а не по строкам `DD.MM.YYYY`), фильтрует по году, месяцу, результату, компании, городу и должности и переключает язык переключателем или `?lang=ru`. Она не сохраняет ничего, кроме темы, ничего не отправляет и не меняет записей; тексты писем, резюме и адреса в неё не попадают. Формат и порядок записи: DATA_CONTRACT.md §9.

### 10.6 Computer Use

Computer Use включается только тогда, когда задаче нужен экран, и только для нужного приложения (в Windows окно должно быть видимым); никогда — чтобы обойти вход, подтверждения Gmail, песочницу или согласие. Перед первым рабочим циклом человек проверяет: открыта нужная папка, права минимальны, учётная запись Gmail правильная, в папке нет секретов, отправка соответствует режиму, тесты используют вымышленные данные, и он знает, что передаётся облачной модели.

## 11. Безопасные критерии готовности

- Случайно открыть документ или почту другого профиля невозможно; это подтверждается отрицательными сценариями, проверенными вручную.
- С каждым значимым фактом связаны источник, дата проверки, статус подтверждения и версия.
- Дубликат работодателя и филиал проверяются; повторная заявка без причины не создаётся.
- Даты и текст пакета совпадают; DOCX/PDF отрисовываются без обрезки и с правильными шрифтами.
- Импорт исходных архивов сначала идёт только на чтение и даёт отчёт о сопоставлении / ошибках.
- Gmail не меняет метки / не архивирует / не удаляет; устранение дубликатов проверяется повторным запуском.
- Статическая `Local_Data/dashboard/index.html` открывается двойным щелчком без сервера и сети; проверены сортировка по годам / датам / результатам, группы месяцев и дней, пометка устаревших данных и отсутствие записей и сетевых запросов.
- В тестах не отправляется ни одно настоящее письмо; отправка требует одобренного режима профиля, точного получателя и вложений.
- Автоматический ответ на отказ и автоматическая подготовка замены не срабатывают на автоматические, временные или неоднозначные сообщения.
- Все события и результаты отчётов можно связать с исходным Gmail Message-ID и с источниками вакансий.
- Лимит в 44 фактические подачи с резюме на человека за календарный месяц нельзя обойти через второй профиль / чат, новый адрес, замену после отказа доставки или другой канал; 45-я отправка блокируется, а очередь не создаёт пакетной рассылки. Проверены общая квота при параллельных задачах и безопасная остановка, когда журнал недоступен.
- Резервную копию можно восстановить; репозиторий GitHub проверен на личные данные и секреты.

Для каждого критерия выполняются соответствующие сценарии из ACCEPTANCE_TESTS.md, а доказательства сохраняются. Пока сценарий не выполнен вручную, его статус — NOT RUN; проверка ссылок в документации не означает, что почта или защитный механизм готовы.
