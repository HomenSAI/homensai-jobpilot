Architecture

Rules and files: the agent keeps the records

There is no separate job-search or mail-sending application. The AI agent follows written rules and maintains local files. The statistics page uses HTML/CSS/JavaScript only to validate, sort, filter and display the agent-written snapshot. No server, Docker or SQL database is needed.

01 · Parts

How the parts fit together

The agent performs the workflow; the local statistics view reads and displays the snapshot. It does not perform mail actions.

↓

↓
The person's journalOne line per completed action; the 44-submission limit is counted from it
GmailThe agent's own authorized mail connection: reading, sending, verification
↓
Documents and local statisticsRecords, queue, DOCX/PDF and an HTML page for each profile

Each person has one authoritative journal, persons/<person_id>/journal/transactions-YYYY-MM.jsonl (monthly segments), and a marker file writer.lock that exists only while one chat is writing. Profile registries, the queue, Status.txt and the statistics can be rebuilt from that journal. Several search profiles share one monthly limit, and a new chat can continue work without sending an application twice.

The safeguards — the limit of 44, never sending twice, one writer at a time — are procedures that the agent must follow, not technical locks. For this reason a new setup only prepares drafts, and automatic sending needs the user's explicit acceptance of this limitation. Detailed architecture · Data contract

03 · Operation

Rules of operation

  • The main work happens in a local Codex or Claude Code chat. The to-do list sets the order of tasks; proof that something was done lives in the journal.
  • The first setup uses draft mode. The queue is stored in the folder and processed by the agent.
  • No more than 44 CV submissions per person per calendar month, across all profiles and channels. A repeat submission or a replacement after a delivery failure uses a slot; a later bounce does not return it.
  • JobPilot blocks its 45th managed CV submission. Independent user submissions do not consume this quota. The manual fallback for a JobPilot package still counts.
  • Reports show used, reserved and remaining slots. A prepared folder or a planned date is not proof of sending.
  • Invitations, positive replies and questions are decided by the person.
  • Confirmed delivery failures are kept. By default at most one suitable new company is prepared as a draft; automatic replacement needs separate permission for that profile.
  • A question about the earliest available internship dates is allowed only under the profile's approved rules, after reading the whole thread and checking that it has not been asked before.
  • The monthly report is neutral, in the chosen language, follows the user's template when one is given, and includes a separate page of market recommendations.
  • Gmail messages are not deleted or archived and labels are not changed.
  • The static HTML page shows data and sorts rows. Personal documents and credentials are never published on GitHub.
04 · Interactive

How the agent works, step by step

Three diagrams you can click. They show the rules the agent follows. Nothing on this page sends mail or changes a file.

1 · The life of one application

Press a stage to see what the agent does there, which journal event it writes and where it stops.

2 · Six checks before sending

Before an application leaves your mailbox, the agent goes through six checks, one after another. If any check fails, the agent stops and sends nothing. Choose a step where something goes wrong (or “none”), press Next step and watch what the agent does. This is only a demonstration: nothing is sent.

    3 · Daily and monthly limits

    Two separate limits. The monthly limit of 44 CV submissions never changes. The daily maximum is a ceiling that the person chooses, from 1 to 43: it says how many may go out on one day at most, not how many have to. Move the slider to see what it means.
