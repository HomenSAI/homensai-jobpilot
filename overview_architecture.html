Architecture

Rules and files: the agent keeps the records

There is no program. The AI agent follows the written rules, records every completed action in a journal file and keeps the other files up to date. No server, Docker or scripts are needed.

01 · Parts

How the parts fit together

There is no program code in the picture: every box is either the agent following a rule or a plain file.

Each person has one authoritative journal, persons/<person_id>/journal/transactions.jsonl, and a marker file writer.lock that exists only while one chat is writing. Profile registries, the queue, inf.txt and the statistics can be rebuilt from that journal. Several search profiles share one monthly limit, and a new chat can continue work without sending an application twice.

The safeguards — the limit of 44, never sending twice, one writer at a time — are procedures that the agent must follow, not technical locks. For this reason a new setup only prepares drafts, and automatic sending needs the user's explicit acceptance of this limitation. Detailed architecture · Data contract

03 · Operation

Rules of operation

  • The main work happens in a local Codex or Claude Code chat. The to-do list sets the order of tasks; proof that something was done lives in the journal.
  • The first setup uses draft mode. The queue is stored in the folder and processed by the agent.
  • No more than 44 CV submissions per person per calendar month, across all profiles and channels. A repeat submission or a replacement after a delivery failure uses a slot; a later bounce does not return it.
  • The plan spreads submissions over the permitted working days and blocks the 45th. Applications made outside the system must be recorded too; a balance that cannot be verified is treated as unavailable.
  • Reports show used, reserved and remaining slots. A prepared folder or a planned date is not proof of sending.
  • Invitations, positive replies and questions are decided by the person.
  • Confirmed delivery failures are kept. By default at most one suitable new company is prepared as a draft; automatic replacement needs separate permission for that profile.
  • A question about the earliest available internship dates is allowed only under the profile's approved rules, after reading the whole thread and checking that it has not been asked before.
  • The monthly report is neutral, in the chosen language, follows the user's template when one is given, and includes a separate page of market recommendations.
  • Gmail messages are not deleted or archived and labels are not changed.
  • The static HTML page shows data and sorts rows. Personal documents and credentials are never published on GitHub.
